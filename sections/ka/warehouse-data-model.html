მონაცემთა არქიტექტურა

საწყობის მოდული ყველა სამარაგო მონაცემს ინახავს FHIR R4 სტანდარტის (Fast Healthcare Interoperability Resources) გამოყენებით. FHIR არის ჯანდაცვის მონაცემების უნივერსალური ენა -- საკუთარი მონაცემთა ბაზის ცხრილების შექმნის ნაცვლად, სისტემა ყველა საწყობის კონცეფციას (მიღება, გადაწერა, მარაგის ნაშთი) ასახავს სტანდარტიზებულ FHIR რესურსებზე. ეს მონაცემებს ხდის პორტატულს, აუდიტირებადს და თავსებადს სხვა ჯანდაცვის სისტემებთან.

ეს სექცია მოიცავს მონაცემთა არქიტექტურის სამ ფენას:

  • FHIR რესურსების შესაბამისობა -- რომელი FHIR რესურსები ინახავს რომელ საწყობის მონაცემებს
  • მარაგის რაოდენობის მოდელი (StockQuant) -- მატერიალიზებული სამარაგო ბალანსის სისტემა, რომელიც უზრუნველყოფს მყისიერ ნაშთის მოძიებას
  • სამუშაო პროცესები და ბიზნეს წესები -- გადაწერის სტატუსები, FEFO კრეფა, გაფრთხილებები და ღირებულების გამოთვლა

FHIR რესურსების შესაბამისობა

საწყობის ყოველი მონაცემი ინახება FHIR რესურსის სახით. ქვემოთ მოცემული ცხრილი აჩვენებს, თუ როგორ შეესაბამება თითოეული საწყობის კონცეფცია FHIR-ის წარმოდგენას. ინტეგრაციის გუნდებისთვის ეს არის საბოლოო ცნობარი საწყობის მონაცემების FHIR API-ით მოთხოვნისთვის.

საწყობის კონცეფცია FHIR რესურსი ძირითადი ველები იდენტიფიკატორის სისტემა
მიღება SupplyDelivery status, მომწოდებელი (Organization ref), დანიშნულება (Location), suppliedItem.quantity, ტიპის კოდი = receipt receipt-number, invoice-number
გადაწერა SupplyDelivery status, წყარო/დანიშნულების განყოფილებები (გაფართოებების საშუალებით), ტიპის კოდი = transfer transfer-document-number
ზედნადები SupplyDelivery იდენტიფიკატორი (10-ნიშნა ზედნადების ნომერი), ტიპის კოდი = waybill, RS.ge ინტეგრაციის მონაცემები waybill-number
შეკვეთა SupplyRequest status, მომთხოვნი განყოფილება, მიმღები განყოფილება, პოზიციები (JSON გაფართოება) order-document-number

პროდუქტები DeviceDefinition მწარმოებელი, მოდელის ნომერი, UDI იდენტიფიკატორი, კატეგორიის გაფართოებები (დღგ, დოზის ფორმა, მარაგის დონეები) product-code
მომწოდებლები Organization სახელი, იდენტიფიკატორი (მომწოდებლის კოდი), ტიპი = supplier, საკონტაქტო ინფორმაცია supplier-id
საწყობები Location სახელი, ტიპი (ფარმაცია, ლაბორატორია, სისხლის ბანკი და ა.შ.), partOf (მშობელი განყოფილება) warehouse-id
ნომენკლატურა List სათაური, entry[] (DeviceDefinition-ის მითითებები), კოდი კატეგორიის/ჯგუფის იერარქიისთვის --
ბაზისური URL ყველა გაფართოებისთვის: ყველა მორგებული FHIR გაფართოება იყენებს ბაზისურ URL-ს http://medimind.ge/fhir. მაგალითად, ერთეულის ფასის გაფართოება არის http://medimind.ge/fhir/StructureDefinition/admin-unit-price. სისტემის ვალუტა არის GEL (ქართული ლარი).

ნომენკლატურის სამდონიანი იერარქია

საწყობის პროდუქტები მიჰყვება სამდონიან კლასიფიკაციას, მსგავსი იმისა, როგორ აწყობს ბიბლიოთეკა წიგნებს სექციებად, თაროებად და ინდივიდუალურ სათაურებად:

დონე სახელი რაოდენობა მაგალითი
1. საგნების ჯგუფი კატეგორიის კლასიფიკაცია ~310 ჯგუფი სახარჯი მასალა, მედიკამენტები, რეაქტივი
2. სამედიცინო საგანი ზოგადი სამედიცინო საგანი ~503 საგანი ქირურგიული ხელთათმანები (ზოგადი)
3. სასაქონლო ერთეული კონკრეტული სამარაგო ჩანაწერი ~35,900 ერთეული ქირურგიული ხელთათმანები, ბრენდი X, ზომა M, 100 ცალიანი ყუთი

ზედა დონის საწყობის ჯგუფები (11 კატეგორია) მოიცავს: სახარჯი მასალა, მედიკამენტები, სამეურნეო, არა ინვენტარი, ძირითადი საშუალებები, ინვენტარი, რეაქტივი, ხსნარი, სამედიცინო ინსტრუმენტი, ნარკოტიკები და კვება.

ოპტიმისტური დაბლოკვა

როდესაც ორი ადამიანი ცდილობს ერთდროულად იგივე მარაგის ბალანსის განახლებას (მაგალითად, ორი მიღება ერთ საწყობში ერთდროულად), სისტემა იყენებს ოპტიმისტურ დაბლოკვას მონაცემთა დაზიანების თავიდან ასაცილებლად. მუშაობის პრინციპი:

  1. მიმდინარე StockQuant ჩანაწერის წაკითხვა (მათ შორის მისი meta.versionId)
  2. ახალი რაოდენობის გამოთვლა
  3. განახლების გაგზავნა If-Match ETag ჰედერით, რომელიც შეიცავს ვერსიის ID-ს
  4. თუ სხვამ ადრე განაახლა ჩანაწერი, სერვერი აბრუნებს 412 Precondition Failed
  5. სისტემა ხელახლა ცდის ექსპონენციალური დაყოვნებით (მაქსიმუმ 5 ცდა, შემთხვევითი ჯიტერით)

ეს მიდგომა თავს არიდებს მონაცემთა ბაზის ბლოკირებას და ამავდროულად გარანტიას იძლევა, რომ მარაგის ცვლილებები არ დაიკარგება კონკურენტული წვდომის პირობებშიც კი.

FEFO კრეფის ალგორითმი

FEFO (First Expired, First Out -- ვადაგასული პირველი გავიდეს) არის სამედიცინო მარაგების მარეგულირებელი მოთხოვნა. მარაგის მოხმარების ან გადაწერის საჭიროებისას სისტემა ავტომატურად გვთავაზობს რომელი პარტია უნდა აიკრიფოს ვარგისიანობის ვადების მიხედვით -- ყოველთვის ყველაზე ადრე ვადაგასული პარტიით იწყება.

მარეგულირებელი შესაბამისობა: FEFO კრეფა სავალდებულოა ფარმაცევტული პროდუქტებისთვის ვადაგასული მარაგის ნარჩენების მინიმიზაციისთვის. FEFO რეკომენდაციის გადახრა მოითხოვს დოკუმენტირებულ მიზეზს (დაზიანებული შეფუთვა, მომხმარებლის მოთხოვნა, პარტიის გამოთხოვა, ხარისხის პრობლემა, ან არასაკმარისი რაოდენობა).

FEFO ალგორითმი მუშაობს სამ ნაბიჯად:

  1. ფილტრაცია -- გამოირიცხება ყველა პარტია, რომელიც ვადაგასულია (ვარგისიანობის ვადა დღეზე ადრე) ან კარანტინში/უარყოფილია. ასევე გამოირიცხება პარტიები ხელმისაწვდომი რაოდენობის გარეშე (სრულად დარეზერვებული).
  2. დალაგება -- დარჩენილი პარტიები ლაგდება ვარგისიანობის ვადით ზრდადობით (ადრეული ვადა პირველი). ვადის გარეშე პარტიები ბოლოში.
  3. აკრეფა -- შეირჩევა პირველი პარტია საკმარისი ხელმისაწვდომი რაოდენობით (quantity - reservedQuantity >= მოთხოვნილი რაოდენობა).
FEFO კრეფის ლოგიკა (ფსევდოკოდი):

1. მოიპოვე ყველა StockQuant (itemCode, locationId, qualityStatus='accepted')
2. ფილტრი: ამოიღე სადაც expiryDate < დღეს
3. ფილტრი: ამოიღე სადაც (quantity - reservedQuantity) <= 0
4. დალაგება: expiryDate ზრდადობით (null-ები ბოლოში)
5. ყოველი კანდიდატისთვის:
     თუ availableQty >= requestedAmount:
       დააბრუნე ეს პარტია    -- აქედან აკრიფე
6. თუ არცერთ პარტიას არ აქვს საკმარისი: გამოტანე InsufficientStockError

როდესაც ახალი მარაგი ჩამოდის არსებული მარაგისგან განსხვავებული ფასით, სისტემა ხელახლა ითვლის ერთეულის ღირებულებას შეწონილი საშუალოს გამოყენებით. ეს უზრუნველყოფს, რომ ერთეულის ღირებულება ასახავს ნაზავის ღირებულებას ყველა მიღებულ პარტიაში.

შეწონილი საშუალო ღირებულების ფორმულა:

  ახალიᲖასი = (არსებულიᲠაოდ x არსებულიᲖასი + მიღებულიᲠაოდ x მიღებულიᲖასი)
               / (არსებულიᲠაოდ + მიღებულიᲠაოდ)

მაგალითი:
  არსებული: 200 აბი 0.30 GEL თითო
  მიღებული: 300 აბი 0.40 GEL თითო

  ახალიᲖასი = (200 x 0.30 + 300 x 0.40) / (200 + 300)
            = (60 + 120) / 500
            = 0.36 GEL აბზე

სპეციალური შემთხვევა: უფასო/შემოწირული საგნები (ღირებულება = 0) არ ამცირებს არსებულ ფასს.
  თუ არსებულიᲠაოდ > 0 და მიღებულიᲖასი = 0:
    unitCost რჩება არსებულᲖასზე (უცვლელი)

ცივი ჯაჭვი და ხარისხის ინსპექცია

ზოგიერთი საწყობის მდებარეობა (ლაბორატორია, სისხლის ბანკი) მოითხოვს ხარისხის კონტროლის დამატებით ნაბიჯებს მიღებისას:

  • ტემპერატურის აღრიცხვა -- ცივი ჯაჭვის საგნებისთვის, მიმღები პერსონალი აღრიცხავს ტემპერატურას მიღების მომენტში. სისტემა ამოწმებს, მოცემულია თუ არა მაჩვენებელი მისაღებ დიაპაზონში (მაგ., 2-8 C ლაბორატორიისთვის, 1-6 C სისხლის ბანკისთვის).
  • ინსპექციის ჩამონათვალი -- პერსონალი ამოწმებს შეფუთვის მთლიანობას, პროდუქტის მდგომარეობას და ეტიკეტირების სისრულეს. საგნები, რომლებიც ვერ გადიან ინსპექციას, ინდება quarantine სტატუსზე განხილვამდე.
  • ხარისხის სტატუსის ნაკადი -- საგნები შემოდის როგორც quarantine (ინსპექციის მომლოდინე), შემდეგ გადადის accepted (გამოყენებისთვის ნებადართული) ან rejected (დაბრუნებული ან განადგურებული). მხოლოდ accepted საგნები ხელმისაწვდომია გადაწერებისა და მოხმარებისთვის.

ბალანსის გამოთვლის სტრატეგია

სისტემა იყენებს ორმაგ სტრატეგიას სამარაგო ბალანსების გამოთვლისთვის:

მეთოდი წარმადობა გამოყენების შემთხვევა
StockQuant მოძიება O(1) -- მყისიერი ძირითადი მეთოდი. კითხულობს წინასწარ გამოთვლილ ბალანსს Basic რესურსიდან.
ძველი ხელახალი გამოთვლა O(n) -- ნელი სარეზერვო, როდესაც StockQuant მონაცემები მიუწვდომელია. სკანირებს 10,000-მდე SupplyDelivery ჩანაწერს ისტორიიდან ხელახალი გამოთვლისთვის.

ბალანსის ქეში იყენებს 30-წამიან TTL-ს (სიცოცხლის დრო) და მხარს უჭერს ჩანართების შორის ინვალიდაციას BroadcastChannel-ის საშუალებით, ასე რომ როდესაც ბრაუზერის ერთი ჩანართი ანახლებს მარაგს, ყველა სხვა გახსნილი ჩანართი ხედავს ცვლილებას 30 წამში.
