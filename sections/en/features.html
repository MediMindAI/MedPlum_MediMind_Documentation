Patient Search & Registration Form

2.1 Patient Search System

The unified patient search system provides fast patient lookup capabilities with both quick search and advanced filtering options. The search supports real-time queries as you type and intelligent detection of search patterns.

Quick Search

The main search bar accepts two types of queries:

  • Name search: Enter any part of the patient's first or last name (minimum 2 characters)
  • Personal ID search: Enter numeric digits to search by Georgian personal ID number
ℹ️
Keyboard Shortcut: Press Cmd+K (Mac) or Ctrl+K (Windows/Linux) to quickly focus the search input from anywhere on the page.

Advanced Filters

Click the Advanced button to access additional search criteria:

Filter Field Description FHIR Path
Personal ID Georgian 11-digit personal identification number Patient.identifier (system: urn:oid:2.16.840.1.113883.3.3785.100.1.1)
First Name Patient's given name(s) Patient.name[0].given
Last Name Patient's family name Patient.name[0].family
Registration Number Hospital visit registration number (format: XXXXX-YYYY) Encounter.identifier

Search Results

Search results appear in a dropdown below the search bar, showing up to 10 patients for quick search or 20 for advanced search. Each result displays:

  • Patient name with personal ID and birth date
  • New Visit button — Opens the visit creation modal
  • Fill Form button — Populates the registration form with patient data for editing
⌨️
Keyboard Navigation: Use ↑ and ↓ arrow keys to navigate results, Enter to select, and Esc to close the dropdown.

2.2 Form Sections

The registration form is organized into 9 collapsible sections that adapt based on whether you're creating a new patient or editing an existing one. The form includes intelligent features like draft auto-save, patient lookup, and visit creation toggle.

Patient Lookup

Enter an 11-digit personal ID to search for existing patients before creating a new record:

  • Automatically searches when 11 digits are entered
  • Validates personal ID using Luhn checksum algorithm
  • If patient found, displays patient card and collapses demographic sections
  • Shows ambulatory and stationary visit counts for existing patients

Found Patient Display

When an existing patient is found, the form displays a patient card and collapses demographic sections to streamline visit registration:

Complete Form View

The unified registration form combines patient demographics and visit information in a single interface:

Draft Auto-Save

The form automatically saves your work to browser localStorage as you type. A draft indicator appears when unsaved changes are detected:

Draft saves occur automatically after 1 second of inactivity. The draft persists across browser sessions and can be cleared using the "Clear Draft" button in the progress indicator.

2.3 Additional Details

The Additional Details section captures supplementary patient information beyond basic personal data. This includes marital status, citizenship, workplace, and other demographic details that support comprehensive patient records.

  • Marital Status — select from standard options (Single, Married, Divorced, Widowed)
  • Citizenship — specify the patient's country of citizenship
  • Workplace — record the patient's current employer or workplace
  • City, District — additional address-level details for precise location tracking
📋
FHIR Mapping: Additional details are stored as extensions on the Patient resource, using standard FHIR extension URLs for marital status (Patient.maritalStatus) and custom extensions for citizenship and workplace.

2.4 Desktop Sidebar

On desktop devices (screens wider than 1025px), a sidebar displays real-time lists of today's visits and recently registered patients. The sidebar provides quick access to active patients without interrupting your current work.

Today's Visits Section

Displays all encounters created today, showing:

  • Time badge indicating when the visit was registered
  • Status badge (e.g., "in-progress", "arrived", "finished")
  • Patient name and registration number
  • Visit type (e.g., "Ambulatory", "Stationary")

Click any visit card to open the visit details modal.

Recent Patients Section

Shows the 5 most recently updated EMR patients (excludes portal patients), displaying:

  • Patient name
  • Personal ID and birth date
  • New Visit button for quick visit creation
  • View button to open patient details
🔄
Auto-Refresh: Both sections automatically update when new patients or visits are created. The Recent Patients list fetches the 30 most recently updated patients and filters out portal patients, displaying the top 10 EMR patients.

2.6 Registration Section

The Registration section configures core visit parameters when the Create Visit toggle is enabled. This section creates an Encounter resource linked to the patient.

Visit Parameters

Field Description FHIR Path
Visit Date Date and time of visit registration (required) Encounter.period.start
Admission Type Ambulatory or Stationary (required) Encounter.class
Stationary Type Admission type for stationary visits (e.g., Emergency, Planned) Encounter.type
Status Visit status (e.g., Planned, Arrived, In Progress) Encounter.status
Department Hospital department handling the visit (required, filtered by admission type) Encounter.serviceProvider (Organization reference)
🏥
Department Filtering: The department dropdown dynamically filters based on the selected admission type. Ambulatory departments appear for ambulatory visits, and stationary departments for stationary visits.

Encounter Creation

When you submit the form with Create Visit enabled, the system creates an Encounter resource:

The encounter includes:

  • Registration number — Auto-generated identifier (format: XXXXX-YYYY)
  • Patient reference — Links to the Patient resource
  • Service provider — Links to the selected Organization (department)
  • Insurance coverage — Links to Coverage resources if insurance is configured

2.7 Insurance Management

The Insurance section allows you to configure up to 3 insurance providers for a patient visit. Each insurer is stored as a FHIR Coverage resource.

Insurance Toggle

The section includes a checkbox to enable/disable insurance. When disabled, the form collapses and no Coverage resources are created. When enabled, the primary insurer card appears.

Multiple Insurers

You can add up to 3 insurers for a single visit:

  • Primary Insurer (#1) — Always visible when insurance is enabled, cannot be removed
  • Secondary Insurer (#2) — Click "Add More" to include a second insurer
  • Tertiary Insurer (#3) — Add a third insurer if needed

Insurer Fields

Field Description FHIR Path
Insurance Company Name of insurance provider (searchable dropdown) Coverage.payor (Organization reference)
Insurance Type Type of insurance policy (e.g., State, Private) Coverage.type
Policy Number Insurance policy identification number Coverage.identifier
Referral Number Authorization or referral number from insurer Coverage.extension (referral)
Copay Percent Patient's copayment percentage (0-100) Coverage.costToBeneficiary
Issue Date Date the insurance policy was issued Coverage.period.start
Valid Until Expiration date of the insurance policy Coverage.period.end
🛡️
Coverage Priority: Each insurer is assigned a priority (order) value in the Coverage resource. Primary = 1, Secondary = 2, Tertiary = 3. This determines the order of claims processing.

2.8 Active Visit Warning

When creating a new visit for a patient who already has an active (in-progress) visit, the system displays a warning modal to prevent duplicate registrations.

Warning Trigger

The modal appears when all of these conditions are met:

  • You submit a form with Create Visit enabled
  • The patient already has an Encounter with status="in-progress"
  • The active encounter was created within the last 24 hours

Modal Contents

The warning displays:

  • Patient name and personal ID
  • List of active visits with registration numbers, visit types, and timestamps
  • Action buttons: Cancel (go back) or Continue Anyway (proceed with duplicate visit creation)
Best Practice: Review the active visit details carefully before proceeding. Creating duplicate active visits can cause confusion in patient history and billing. If the visit is a genuine new admission (e.g., emergency readmission), click "Continue Anyway."

2.9 Demographics Section

The Demographics section collects address and social information for statistical and administrative purposes. This section is visible when Create Visit is enabled.

Address Information

Field Description FHIR Path
Region Georgian administrative region (e.g., Tbilisi, Adjara) Patient.address[0].state
District District within the selected region (filtered by region) Patient.address[0].district
City City or town name Patient.address[0].city
Actual Address Street address and apartment number Patient.address[0].line

Social Information

Field Description FHIR Extension
Education Highest level of education completed (e.g., Higher, Secondary) Patient.extension (education)
Family Status Marital status (e.g., Married, Single, Divorced) Patient.maritalStatus
Employment Employment status (e.g., Employed, Unemployed, Retired) Patient.extension (employment)
🗺️
Copy from Patient: The "Copy from Contact Info" button (top-right of section) automatically populates address fields from the patient's contact information section, saving time during registration.
🔗
Cascading Dropdowns: The District field is dynamically filtered based on the selected Region. Select a region first before choosing a district.
