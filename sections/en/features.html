Features

Patient refers to the permanent medical record, while a Visit (encounter) represents a single hospital interaction. You can register a patient on its own, or register a patient and create a visit at the same time.

1. Finding a Patient

The registration module features a powerful search system that serves as the primary way to find existing patients.

Hero Search Component

The hero search bar is prominently displayed at the top of the registration page:

Feature Description Keyboard Shortcut
Quick Search Auto-detects if input is personal ID (11 digits) or name Cmd/Ctrl + K
Advanced Filters Expand panel for Personal ID, First Name, Last Name, Reg Number Cmd/Ctrl + Shift + K
Navigate Results Move through search results ↑ / ↓
Select Result Choose highlighted result Enter
Close Search Close search panel Escape

Advanced Filters Panel

Click the "Advanced" button or use Cmd/Ctrl + Shift + K to open detailed filters:

  • Personal ID - Personal ID number (or passport number for foreign nationals)
  • First Name - Patient's given name
  • Last Name - Patient's family name
  • Registration Number - Internal EMR registration number

Search Results with Dual Actions

When you search for a patient by name or personal ID, matching results appear in a dropdown with two action buttons:

Each search result displays two action buttons:

New Visit
Creates a new visit for this patient and navigates to visit details
Fill Form
Populates the registration form with patient data for editing

Patient Lookup Section

Within the form, a dedicated field lets you look up patients by their personal ID:

How Patient Lookup Works:
  • Enter the patient's personal ID
  • The system searches automatically as you type
  • If found: displays patient card with name, date of birth, and visit count
  • If not found: allows new patient registration

Patient Found Card

When an existing patient is found, a card displays their details with options to edit or create a new visit:

Duplicate Detection

If you attempt to register a patient with a personal ID that already exists in the system, a duplicate detection modal appears:

  • Automatic check - Triggered when personal ID is entered and matches an existing record
  • Patient card preview - Shows the existing patient's name, DOB, and visit history
  • Options - View existing patient, fill form with their data, or proceed with new registration
Preventing Duplicates:

The system uses the 11-digit Georgian personal ID as a unique identifier. When a match is found, you are encouraged to use the existing record rather than creating a duplicate.

Unknown Patient Mode

For emergency situations where a patient's identity cannot be established, the Unknown Patient toggle allows registration without a personal ID:

  • Toggle location - Available in the Patient Lookup section
  • Auto-generated name - System assigns a temporary name (e.g., "Unknown Patient #12345")
  • Auto-generated ID - A temporary personal ID is created automatically
  • Later identification - Record can be updated when patient identity is confirmed
When to use Unknown Patient:
  • Emergency admissions where patient is unconscious or unable to communicate
  • Temporary registration pending identity verification
  • Foreign nationals without Georgian personal ID (before passport entry)

Create Visit Toggle

The form includes a toggle to control whether a visit is created along with the patient:

Create Visit: ON

Patient + Visit created together. Registration, Insurance, Guarantee, and Demographics sections visible.

Create Visit: OFF

Patient only created. Visit-related sections hidden.

Draft Auto-Save

The form automatically saves your progress as you type:

3. Visit Details

When the visit creation option is enabled, visit-related sections become available in the form:

Creating a New Encounter

After finding an existing patient, the form shows their details and the visit registration fields for creating a new encounter:

Registration Section

Field Description
Visit Type Outpatient, Inpatient, or Emergency
Visit Date Date of the visit
Department Target department/service
Referring Doctor Doctor who referred the patient (optional)

Visit Types

The system supports three visit types, each with different workflows:

Type FHIR Code Description Conditional Fields
Outpatient AMB Scheduled or walk-in visit, patient returns home same day Department, Referring Doctor
Inpatient PLAN_STAT Planned hospital admission for treatment or surgery Department, Bed assignment, Expected duration
Emergency EMER_STAT Urgent unplanned admission via emergency department Department, Triage level

Insurance Section

Add up to 3 insurance companies per visit:

  • Insurance Company - Select from registered insurers
  • Policy Number - Patient's policy number
  • Coverage Type - Full, partial, or specific coverage
  • Add/Remove Buttons - Manage multiple insurers

Guarantee Section

The Guarantee section includes document upload for attaching guarantee letters and supporting documents:

Document Upload Features
  • Drag & Drop - Drag files directly onto the upload zone
  • Click to Browse - Click the zone to open file picker
  • Multiple Files - Up to 5 files per guarantee
  • Multiple Guarantees - Up to 3 guarantees per registration
  • Document Metadata - Name, date, author, document number
Field Description Required
Document Name Descriptive name for the document Yes
Document Date Date the document was issued Yes
Author Person or organization that issued the document No
Document Number Reference number on the document No
File Attachment The actual file (PDF, image, etc.) Yes

Demographics Section

Additional demographic data collected during visit registration:

  • Region - Patient's residential region
  • Chief Complaint - Primary reason for visit
  • Referral Source - How patient was referred

Active Visit Warning

If a patient already has an in-progress visit, a warning modal appears:

Active Visit Detection:

The system prevents duplicate encounters by detecting in-progress visits. You can choose to:

  • View the existing active visit
  • Create a new visit anyway (with confirmation)
  • Cancel and return to the form
