9 Administration Overview

9.1 Module Overview

The Administration section is a comprehensive warehouse and inventory management module for tracking medical supplies, medications, and equipment across hospital departments. It provides complete lifecycle management from supplier receipts through internal transfers to real-time inventory balances.

All inventory data is stored as FHIR SupplyDelivery and SupplyRequest resources on the Medplum server, ensuring standards-compliant interoperability and audit trails for every inventory movement.

  • Receive goods from external suppliers with invoice tracking and RS import
  • Transfer supplies between departments with confirmation workflows
  • Process orders from departments with multi-stage approval
  • Monitor balances in real time across all warehouses and departments
  • Export reports to Excel with Georgian-language headers and summary rows
  • Group views for aggregated receipt, transfer, and order analysis

9.2 Business Domains

The Administration module is organized into four business domains, each handling a distinct aspect of inventory management:

Reception (Supplier Receiving)
3 pages: ReceptionPage, ReceptionsPage, ReceptionGroupPage. Create receipts from suppliers, view and filter all receivings, and access grouped invoice views. Supports RS import for bulk receipt creation.
Transfer (Inter-department Movement)
4 pages: TransferConfirmationPage, TransferCreatePage, TransferPage, TransferGroupPage. Create transfers between departments, manage confirmation workflows, and support direct write-off operations.
Order (Department Requests)
4 pages: OrderConfirmationPage, OrderPage, OrdersPage, OrderGroupPage. Departments create supply orders, warehouse staff confirm with 3-section approval, and track delivery status through completion.
Balances (Inventory Status)
1 page: BalancesPage. Real-time inventory levels computed from all movements. Features 12 filter fields and a 9-column data table with 30-second cache for optimal performance.

9.6 Key Architectural Decisions

FHIR Resource Selection:
  • Receipts and Transfers use SupplyDelivery resources, differentiated by type field (receipt vs. transfer)
  • Orders use SupplyRequest resources with status tracking through the full lifecycle
  • Balances are computed values derived from aggregating all SupplyDelivery movements -- they are not stored as separate FHIR resources
Line Items Storage Strategy:
  • Receipts and Transfers store each line item as a separate FHIR resource, enabling independent queries and updates per item
  • Orders store all line items as JSON within a FHIR extension, keeping the entire order as a single atomic resource
Document Number Generation:

All receipts, transfers, and orders receive an auto-generated 10-digit document number upon creation. This number serves as the primary human-readable identifier across all Administration views and is stored in the FHIR resource's identifier field.

Search Performance Optimizations:
  • _tag parameter is used for server-side filtering, enabling efficient queries without client-side post-processing
  • 30-second cache on the Balances page prevents redundant API calls during rapid navigation
  • Pagination limits result sets to manageable sizes (e.g., last 20 entries on ReceptionPage)
