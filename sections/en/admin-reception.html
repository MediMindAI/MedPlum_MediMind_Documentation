10 Reception System

10.1 Overview

The Reception system consists of 3 interconnected pages for receiving goods from external suppliers into the hospital warehouse. All receipt data is stored as FHIR SupplyDelivery resources with type=receipt, providing a complete audit trail of every incoming shipment.

  • ReceptionPage - Quick entry interface with last 20 receipts and fast creation
  • ReceptionsPage - Full receivings list with comprehensive filtering and export
  • ReceptionGroupPage - Aggregated view grouped by invoice number
FHIR Resource: Each receipt and its line items are stored as individual SupplyDelivery resources with type: "receipt". The header document and each line item are separate resources, linked by a shared document number identifier.

10.2 ReceptionPage (Quick Entry)

The ReceptionPage serves as the primary entry point for warehouse staff to create new receipts and review recent receiving activity. It displays the last 20 receipt entries with pagination for quick reference.

10.3 Receipt Creation

The ReceiptFormModal provides a two-part form for creating new receipts: a header section with document metadata and a line items section for individual products.

Header Fields

Field Type Description Required
receiptDate DatePicker Date of the receipt, defaults to today Yes
receiptNumber Auto-generated 10-digit unique document number, generated on creation Auto
supplierId Select Supplier company selection from ~495 registered organizations Yes
warehouseId Select Target warehouse/department receiving the goods Yes

Line Item Fields

Field Type Description Required
productCode / productSearch Autocomplete Bidirectional product search across ~33,900 items (search by code or name) Yes
unit Text Unit of measure (e.g., pcs, box, vial) Yes
quantity Number Number of units received Yes
purchasePrice Number Purchase price per unit from the supplier Yes

Bidirectional Autocomplete:

The product search field supports bidirectional lookup across approximately 33,900 items. You can type a product code to find the item name, or type a product name to find its code. Results appear as you type with debounced server-side search for optimal performance.

10.5 Export Functionality

The Receptions list supports data export for reporting and analysis purposes:

Excel Export
Dynamic import of xlsx library. Generates spreadsheet with Georgian-language column headers, all filtered data rows, and a summary row with totals. Filename includes date stamp (e.g., "Receptions_2024-01-15.xlsx").
PDF Export
PDF export functionality (placeholder - planned for future implementation). Will generate a printable document with the same data and layout as the Excel export.
Excel Export Details:
  • Uses dynamic import('xlsx') to minimize initial bundle size
  • Column headers are in Georgian language for local compliance
  • Includes a summary row at the bottom with column totals
  • Filename format: Receptions_YYYY-MM-DD.xlsx with the current date
  • Exports only the currently filtered dataset, not all records

Composite Grouping Key:

Receipts are grouped using a composite key derived from: invoiceNumber + supplierId + warehouseId + date. This ensures that multiple deliveries from the same supplier on the same invoice are correctly aggregated, even if they arrive on different dates or to different warehouses.

Existing receipts can be edited or deleted through the ReceivingEditModal, accessible from any receipt row in the table views.

Delete Operation:

Deleting a receipt permanently removes the SupplyDelivery resource from the FHIR server. This operation cannot be undone. Only receipts with status=draft or status=in-progress can be deleted. Completed receipts that have already affected inventory balances require an offsetting transaction instead.

10.8 FHIR Mapping

The Reception system maps warehouse receipt operations to FHIR SupplyDelivery resources:

Receipt Concept FHIR Path Description
Resource Type SupplyDelivery Base FHIR resource for all receipts
Receipt Type SupplyDelivery.type Set to "receipt" to distinguish from transfers
Status SupplyDelivery.status draft | in-progress | completed | abandoned
Document Number SupplyDelivery.identifier[0] 10-digit auto-generated receipt number
Invoice Number SupplyDelivery.identifier[1] Supplier invoice reference
Receipt Date SupplyDelivery.occurrenceDateTime When the goods were received
Supplier SupplyDelivery.supplier Reference to Organization resource
Warehouse SupplyDelivery.destination Reference to Location resource
Product SupplyDelivery.suppliedItem.itemReference Reference to Device or Medication resource
Quantity SupplyDelivery.suppliedItem.quantity Number of units received
Pricing SupplyDelivery.extension Custom extensions for purchase/sale prices
Tag SupplyDelivery.meta.tag Used with _tag parameter for efficient server-side filtering

10.9 Troubleshooting

Common issues encountered when using the Reception system:

Issue Cause Solution
Product search returns no results Search term is too short or product catalog not loaded Enter at least 3 characters. Check network connectivity and refresh the page.
Supplier dropdown is empty Organization resources not loaded from FHIR server Refresh the page. Verify the Medplum server is accessible and Organization resources exist.
Receipt number not generated Server-side number generation failed Check FHIR server connectivity. The 10-digit number is generated on resource creation.
Excel export produces empty file No data matches the current filter criteria Clear or adjust filters to include data. The export only includes filtered results.
RS import fails Revenue Service connection issue or invalid data format Verify RS service availability. Check that the import data format matches expected schema.
Cannot delete completed receipt Completed receipts are protected to maintain inventory integrity Only draft or in-progress receipts can be deleted. Create an offsetting transaction for corrections.
Totals not recalculating Computed fields require both quantity and price to be set Ensure both quantity and price fields have valid numeric values. Check for non-numeric characters.
Group view shows duplicate entries Multiple receipts with the same invoice number but different dates/warehouses This is expected behavior. The composite grouping key includes date and warehouse. Use filters to narrow results.
