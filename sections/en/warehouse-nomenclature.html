Product Nomenclature Overview

The Warehouse Nomenclature module is the central product catalog for the entire hospital supply chain. Think of it as the hospital's master product library -- every medication, consumable, piece of equipment, and supply item used across all departments is organized here in a structured, searchable hierarchy.

Just like a library uses a classification system (shelves, sections, sub-sections, and individual books), the warehouse nomenclature organizes products into 5 hierarchical tiers. This makes it easy to find any item among tens of thousands of products, and ensures consistent naming and grouping across departments.

FHIR R4 Compliant: All nomenclature data is stored using FHIR R4 resources. Categories, groups, sub-categories, and generic names use List resources, while individual warehouse products use SupplyDelivery resources. The item edit modal uses DeviceDefinition for extended product attributes.

Categories (Level 1)

Categories are the broadest classification tier -- the top-level "shelves" in your product library. They divide the hospital's entire inventory into major functional groups such as Medications, Consumables, Equipment, and Food. The system comes with 12 predefined categories, and administrators can add custom ones.

Managing Categories

The Categories tab provides a simple interface for viewing and managing top-level categories:

  • Add Category -- Type a name in the "Add" form and press the + button (or press Enter). The new category appears immediately in the list.
  • Search -- Use the search bar to filter categories by name in real time.
  • Edit -- Click the edit (pencil) icon on any row. The name becomes an editable text field. Press Enter or click away to save.
  • Delete -- Click the delete (trash) icon. A confirmation dialog appears before the category is removed.
  • Status -- Each category displays an active/inactive status badge with a colored dot indicator.
Caution: Deleting a category does not automatically reclassify the product groups assigned to it. Reassign product groups to another category before deleting to avoid orphaned records.
3

Product Groups (Level 2)

Product Groups are the second tier of the hierarchy. If categories are the "shelves," then product groups are the labeled sections on each shelf. They represent functional groupings within a category -- for example, within the "Medications" category, you might have groups like "Antibiotics," "Analgesics," and "Cardiovascular."

The system contains over 310 product groups, and each one can optionally belong to a parent category.

Group Table Columns

Column Description
Name The group name (editable inline by clicking the edit icon)
Parent Category Which Level 1 category this group belongs to, shown with a tag icon. Displays "-" if unassigned.
Item Count A blue badge showing the number of generic names (Level 4 items) in this group
Status Active or inactive status badge

Adding a Product Group

  1. Type the group name in the text field.
  2. Optionally select a Parent Category from the searchable dropdown. This links the group to a Level 1 category.
  3. Click the + button or press Enter.

Cross-Filtering

One of the most powerful features of the nomenclature module is cross-filtering. When you click on a product group row, the system automatically:

  1. Switches to the Generic Names tab (Level 4)
  2. Filters the list to show only generic names belonging to that group
  3. Displays a blue filter bar at the top indicating which group is active

This allows you to quickly drill down from a broad group to its specific items without manually switching tabs and searching. Click the X button on the filter bar to clear the filter and see all items again.

Keyboard Shortcut: You can also search for groups by name using the search bar at the top of the table. Search is applied in real time as you type.

Sub-Groups (Level 3)

Sub-Groups provide a third level of refinement within each product group. While product groups divide a category into functional areas (e.g., "Antibiotics"), sub-groups break those areas down further (e.g., "Cephalosporins," "Penicillins," "Macrolides"). This extra granularity helps pharmacists and procurement staff locate items faster.

The Sub-Groups tab follows the same layout pattern as Categories and Product Groups:

Column Description
Name The sub-group name (editable inline)
Parent Group The Level 2 product group this sub-group belongs to
Item Count Number of generic names (Level 4) assigned to this sub-group
Status Active or inactive status badge

To add a new sub-group, type the name, select a parent product group from the dropdown, and click +. Clicking a sub-group row triggers cross-filtering to the Generic Names tab, showing only items in that sub-group.

4

Generic Names & Product Catalog

The last two tiers bring us to the individual product level. Generic Names (Level 4) are standardized medical item names -- the "what it is" without specifying a brand. The Product Catalog (Level 5) contains the actual warehouse products with specific brands, dosages, suppliers, and packaging.

Generic Names (Level 4)

Generic names represent over 500 standardized medical item names. Each generic name belongs to a sub-group (Level 3) and aggregates one or more specific warehouse products. For example, the generic name "Ceftriaxone" might have 15 warehouse products from different manufacturers and in different package sizes.

The table displays four columns:

Column Description
Name The standardized generic name. An arrow icon appears next to each name, indicating it is clickable for cross-filtering.
Sub-Group The Level 3 sub-group this item belongs to, displayed as a blue badge
Warehouse Count A teal badge showing how many specific warehouse products reference this generic name
Status Active or inactive status badge (hidden on mobile devices)

When a group filter is active (from clicking a Product Group row on Level 2), a blue alert bar appears at the top showing which group is selected, with a close button to clear the filter.

Clicking a generic name row triggers a second cross-filter: the system switches to the Product Catalog tab and filters it to show only products under that generic name. This creates a seamless drill-down flow: Group > Generic Name > Specific Products.

Product Catalog (Level 5)

The Product Catalog is the largest and most detailed tier, containing over 36,500 individual product records. This is where every specific item in the hospital's inventory is defined -- with its exact name, code, manufacturer, unit of measure, and category.

Search and Filters

The product catalog provides three filter controls in a horizontal row above the table:

  • Search -- Real-time text search across product name, code, and barcode. The search is debounced (300ms delay) to avoid overloading the server with requests while you type.
  • Category Filter -- Dropdown to filter by warehouse group (Consumables, Medications, etc.). Select "All" to see all categories.
  • Status Filter -- Dropdown to show active items only, deleted items only, or all items. Defaults to "Active."
Server-Side Pagination: Because the product catalog contains over 36,500 items, the table uses server-side pagination with 50 items per page. The page counter at the bottom shows "X / Total" (e.g., "50 / 36,513"). Data loads on-demand as you navigate pages to avoid loading the entire 22MB dataset.

Cross-Filter Indicator

When you arrive at the Product Catalog via cross-filtering (clicking through from Group or Generic Name), a blue filter alert appears at the top showing which parent items are selected. The alert includes:

  • A blue badge for the selected product group (Level 2)
  • An arrow separator
  • A teal badge for the selected generic name (Level 4)
  • Close buttons on each badge to clear individual filters
  • A global clear button to remove all filters at once

Adding a New Product

Click the "Add Product" button above the table to open the product creation modal. If you navigated via cross-filter, the group and generic name fields are pre-populated automatically.

The creation modal includes the following fields:

  • Product Name -- The full name of the product (required).
  • Product Code -- An internal code for identification.
  • Product Group & Generic Name -- Pre-filled if you arrived via cross-filter; otherwise select from searchable dropdowns.
  • Category, Unit, Manufacturer -- Classification and packaging details.

Row Actions

Each product row has two actions available via the action buttons column:

  • Edit (pencil icon) -- Opens the full item edit modal (see Section 5 below)
  • Delete (trash icon) -- Soft-deletes the item after confirmation. Deleted rows appear highlighted in red if the status filter includes deleted items.
5

Item Edit Modal

Clicking the edit icon on any product row opens a full-width modal with detailed product configuration. This is where hospital staff can manage all extended attributes of a product -- from pharmaceutical details to stock management parameters.

The modal is organized into two tabs:

Main Tab

The Main tab contains the core product attributes organized into individual sections. Each section has its own Save button, allowing you to save changes to one section without affecting others. This section-by-section save approach prevents accidental overwrites when multiple users edit the same item.

Step-Up Authentication: Saving any section in the edit modal requires re-authentication. When you click Save, a password confirmation dialog appears. This protects critical product data from unauthorized modifications.
