Product Hierarchy

The warehouse module organizes all products using a 5-tier hierarchy. Think of it like folders on a computer: broad categories at the top, and specific items at the bottom. Each level narrows down the classification, making it easy to find and manage thousands of products.

Cross-Filtering

A key feature of the nomenclature system is cross-filtering. Clicking on an item at any level automatically filters the next level down:

  • Click a Product Group to see only the Generic Names belonging to that group
  • Click a Generic Name to see only the Product Catalog items for that product
  • Active filters appear as badges at the top of the page, and can be cleared individually or all at once

Categories & Groups

The first three levels of the hierarchy provide the organizational framework for all warehouse products.

Categories (Level 1)

Categories are the broadest classification. The system comes pre-configured with standard hospital warehouse categories such as Consumable Materials, Medications, Household Supplies, Reagents, and Medical Instruments.

Each category tab provides:

  • Add new item — Type a name and press Enter or click the add button
  • Search — Filter the list by typing in the search bar
  • Inline edit — Click the edit button on any row to rename directly in the table
  • Delete — Remove items with a confirmation dialog to prevent accidental deletion
  • Status indicator — Green dot for active items, gray for inactive
  • Pagination — 25 items per page for fast loading

Product Groups (Level 2)

Product Groups organize items within categories. Each group belongs to a parent category and tracks how many Generic Names it contains.

The Groups tab adds these features beyond the standard list:

  • Parent Category column — Shows which category each group belongs to
  • Item Count badge — Displays how many Generic Names are in each group
  • Row click navigation — Click any group row to cross-filter to its Generic Names
  • Category selector — When adding a new group, optionally assign it to a parent category
ℹ️
Sub-Groups (Level 3) provide optional finer classification within Product Groups. They work the same way as Categories and Groups but are used less frequently. The Sub-Groups tab follows the same add/search/edit/delete pattern.

Product Catalog

The bottom two levels contain the actual product data used in day-to-day warehouse operations.

Generic Names (Level 4)

Generic Names represent standard product names without brand or manufacturer specifics. For example, "Amoxicillin" is a generic name, while "Amoxicillin 500mg Tablet by GlaxoSmithKline" is a specific catalog item.

The Generic Names tab shows:

  • Sub-Group badge — Which sub-group (or product group) this item belongs to
  • Warehouse Count — Number of specific catalog items linked to this generic name
  • Group filter alert — When cross-filtered from a Product Group, a blue alert shows the active filter with a clear button
  • Row click navigation — Click any generic name to cross-filter to its Product Catalog items

Product Catalog (Level 5)

The Product Catalog is the most detailed level, containing specific warehouse items with full attributes. This is where you manage the actual products that are stocked, distributed, and tracked in the hospital.

The Product Catalog table has 13 columns that display comprehensive item information:

Column Description FHIR Path
ID Original database identifier SupplyDelivery.identifier
Code Product code (SKU) SupplyDelivery.identifier (code system)
Name Full product name with dosage and form SupplyDelivery.suppliedItem.itemCodeableConcept
Product Group Parent group from Level 2 Extension: general-group
Generic Name Generic name from Level 4 Extension: general-name
Category Top-level category (Consumables, Medications, etc.) SupplyDelivery.type
Unit Measurement unit (piece, ml, box, ampoule, etc.) SupplyDelivery.suppliedItem.quantity.unit
Manufacturer Country/manufacturer of the product Extension: manufacturer
Quantity Current stock quantity SupplyDelivery.suppliedItem.quantity.value
Description Additional product description Extension: description
Deleted Soft-delete status (Yes/No) SupplyDelivery.status
Parent Parent item reference (for bundled products) Extension: parent-item
Price Calculation Pricing visibility rules for billing Extension: price-calculation-mode

The catalog supports server-side pagination (50 items per page) and provides three filter controls:

  • Text search — Filter by product name with debounced input (300ms delay for performance)
  • Category filter — Dropdown to filter by top-level category
  • Status filter — Show active items, deleted items, or all
Note: Deleted items appear with a red highlight in the table. Items are soft-deleted (marked as deleted) rather than permanently removed, preserving the audit trail for compliance.

Click the edit button on any catalog item to open a detailed edit modal. The modal has two tabs:

Main Tab contains these editable sections, each with its own Save button:

ℹ️
Step-Up Authentication: Saving changes to catalog items requires re-authentication. When you click Save, a confirmation dialog prompts you to verify your credentials before the change is applied. This protects against unauthorized modifications to the product database.
FHIR Data Model Details

The nomenclature hierarchy is implemented using these FHIR resources:

  • List (with different code values) — Stores Levels 1-4 as list entries. Each list entry contains the item name and status. Parent-child relationships are maintained through entry references.
  • SupplyDelivery — Stores Level 5 catalog items with their full attributes (code, name, category, unit, quantity). FHIR extensions carry additional data like manufacturer, pricing rules, and group links.
  • DeviceDefinition — Used for the edit modal, providing detailed attributes like VAT, pharmaceutical details, stock levels, lot tracking, and transaction history.
