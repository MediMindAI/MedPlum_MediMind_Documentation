Architecture

Architecture Overview

The registration module follows a layered architecture pattern:

flowchart TB subgraph UI["UI Components"] UnifiedReg[UnifiedRegistrationView] PatientForm[PatientForm] VisitModal[VisitModal] SearchPanel[SearchPanel] end subgraph Hooks["React Hooks"] useRegForm[useRegistrationVisitForm] useDept[useDepartments] useIns[useInsuranceData] end subgraph Services["Services Layer"] EncSvc[encounterService] MedClient[MedplumClient] DeptSvc[departmentService] end subgraph FHIR["Medplum Cloud"] DB[(FHIR R4 API)] end UI --> Hooks Hooks --> Services Services --> FHIR

FHIR Resources

The registration module creates and manages the following FHIR R4 resources:

Resource Purpose Created When
Patient Core patient demographic record Every registration
Encounter Hospital visit / encounter record When "Create Visit" is ON
Coverage Insurance coverage details When insurance is added
RelatedPerson Guardian / representative info When guardian is entered
DocumentReference Uploaded guarantee documents When files are attached

FHIR Resource Creation Flow

When a registration is submitted, the following FHIR resources are created:

sequenceDiagram participant U as User participant F as Form participant S as Service participant M as Medplum U->>F: Submit Registration F->>S: createPatient() S->>M: POST /Patient M-->>S: Patient ID F->>S: createEncounter() S->>M: POST /Encounter M-->>S: Encounter ID F->>S: createCoverage() S->>M: POST /Coverage M-->>S: Coverage ID S-->>F: Success F-->>U: Registration Complete
