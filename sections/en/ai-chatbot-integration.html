AI Chatbot — IT Integration

This section covers the technical architecture of the AI Medical Chatbot for IT administrators: FHIR data model, AI services, voice services, and security.

High-Level Architecture

The chatbot connects the React frontend to external AI services through Supabase Edge Functions, with FHIR-based data persistence via Medplum.

flowchart LR A[React Frontend] -->|SSE Request| B[Flowise AI] A -->|Edge Functions| C[Supabase] A -->|FHIR API| D[Medplum Server] B --> E[Knowledge Bases] B --> F[LLM Models] C --> G[STT Services] C --> H[OCR Services]

FHIR Data Model

The AI chatbot uses FHIR R4 resources for data persistence. All custom extensions follow the pattern: http://medimind.ge/fhir/StructureDefinition/{name}

Data Persistence

The chatbot uses a hybrid FHIR + local storage approach for optimal performance:

flowchart TD A[User Action] --> B[Update UI State] B --> C[Save Locally] C --> D[Save to FHIR] D --> E{Success?} E -->|Yes| F[Complete] E -->|No| G[Fallback to Local Storage] G --> F style C fill:#f59e0b,stroke:#d97706,color:#000 style D fill:#10b981,stroke:#059669,color:#fff
Benefits: Instant UI updates without waiting for server response, offline capability, cross-device sync via FHIR, and data survives browser clear.

Reliability & Security

Error Handling & Resilience

Service Max Retries Backoff Timeout
Flowise SSE 3 Exponential (1s, 2s, 4s) 180s
Enagram STT 2 Fixed (1s) 30s
Google STT 2 Fixed (1s) 30s
Patient Chatbot 2 Fixed (1s) 30s
Gemini OCR 1 None 30s
Fallback Chain:
  1. Streaming fails — Retry 3x with backoff, then fall back to standard JSON response
  2. OCR fails — Client-side OCR fails, fall back to cloud-based AI vision
  3. STT fails — Display notification, allow manual text entry
  4. FHIR fails — Save locally, background sync on next load

Security

Concern Mitigation
API key exposure All keys stored in server secrets, never in frontend code
Patient data in AI prompts Patient context uses anonymized summaries (age ranges, no PII)
CORS Edge functions restrict origins to medimind.ge and localhost
Rate limiting Server-side throttling on all AI endpoints
Authentication Supabase anon key for edge functions; Medplum OAuth for FHIR
Data transit All connections use HTTPS/TLS
XSS in AI responses Markdown renderer sanitizes HTML before display
