Warehouse Operations

The Warehouse Operations module handles the three core supply chain activities in the hospital: Receiving goods from external suppliers, Transferring items between departments, and Ordering supplies from other departments. Together these operations form the backbone of inventory movement — every item that enters, leaves, or moves within the hospital is tracked through one of these three workflows.

3.1 Receiving (Goods Receipt)

The Receiving module records all goods arriving at the hospital from external suppliers. Think of it as the hospital's "front door" for inventory — every item that enters the supply chain starts here. Each receipt is tied to a supplier invoice and creates FHIR SupplyDelivery resources that automatically update stock balances.

Page Layout

The Receiving page uses a 2-tab layout with shared header actions:

  • Receiving History — Grouped invoice table showing all received shipments with filters, sorting, and export
  • Analytics — KPI summary cards and detailed analytics charts for receiving trends

Two action buttons appear in the page header, available from either tab:

  • Import from RS — Import invoice data from the RS (Revenue Service) electronic invoicing system
  • Create Receipt — Create a new receipt manually by entering supplier and item details

Receiving History

The Receiving History tab displays all receiving records grouped by invoice number. Each row represents one invoice from a supplier, showing the total quantity and value of all items on that invoice. Clicking a row opens a detail modal with the individual line items.

Export Options: Click the Excel or CSV button in the Receiving History tab header to export all filtered receiving records. The Excel export includes all columns plus package quantity and package price fields.
Invoice Detail Modal

Clicking on any invoice row opens the Invoice Detail Modal, which shows every individual line item on that invoice. From this modal you can:

  • View all items received under that invoice number with item codes, names, quantities, and prices
  • Edit individual line item details (requires step-up authentication)
  • Delete individual line items (requires step-up authentication and appropriate permissions)
Step-Up Authentication: Editing or deleting receiving records requires re-entering your password. This extra security step prevents accidental modifications to financial records. Only admin users (level 4+) or users assigned to the receiving department can delete records.

Analytics Tab

Click "Create Receipt" or "Import from RS" to open the receipt creation modal. The form has two parts: a header section for invoice-level details and a line items section for individual products.

Line Items

Each line item represents one product being received. Use the item picker to search by name or barcode, then enter the quantity and price. You can add multiple line items to a single receipt.

  • Item search — Type a product name or scan a barcode to find items from the warehouse nomenclature
  • Quantity — Number of units received
  • Unit Price — Price per unit in GEL
  • Package Quantity / Price — Optional package-level pricing for bulk items
  • Total — Auto-calculated (quantity x unit price)
  • Add / Remove — Click the + button to add a line item; click the trash icon to remove one
RS Import: Instead of manual entry, you can use Import from RS to pull invoice data directly from Georgia's Revenue Service electronic invoicing system. This pre-fills the supplier, invoice number, and all line items automatically.

3.2 Transfers (Inter-Department Movement)

Transfers track the movement of supplies between hospital departments. When the pharmacy needs to send medications to the ICU, or the main warehouse distributes consumables to the surgical ward, a transfer record is created. Each transfer generates a FHIR SupplyDelivery resource with type "transfer" and follows an approval workflow before items physically move.

Page Layout

The Transfers page uses a 3-tab layout with a shared header action button:

  • Transfer History — Flat list of every individual transfer line item with edit/delete/correct actions
  • Analytics — One row per document number with KPI analytics and export options
  • Needs Confirmation — Transfers awaiting confirmation from the receiving department

The header contains a single action button:

  • New Transfer — Opens the Transfer Book modal to create a new transfer with multiple line items

Transfer History

The Transfer History tab shows every transfer line item as a separate row. If a transfer document has 5 items, each appears as its own row, grouped visually by document number. This view is useful for finding and editing individual items.

Row-level actions include:

  • Edit — Change the From/To departments, quantity, or price of a single line item
  • Delete — Remove the transfer line item entirely (with confirmation dialog)
  • Correct — Open the warehouse correction modal to create an adjustment entry that reverses or modifies this transfer
Edit Restrictions: Only transfers in an editable status (draft, requested) can be modified. Once a transfer is approved or completed, use the Correct action to create an adjustment instead of directly editing.

Analytics

The Analytics tab aggregates transfers by document number, showing one row per transfer document. This gives a higher-level view of transfer activity and includes analytics features not available in the Transfer History tab.

Clone Feature: The Clone action on a grouped document opens the Transfer Book pre-filled with the same From/To departments, making it easy to repeat a common transfer route.

Needs Confirmation

The Needs Confirmation tab shows transfers that have been created but not yet confirmed by the receiving department. This is the core of the transfer approval workflow — it ensures that the receiving department verifies what was actually received before inventory balances are updated.

Workflow Lifecycle

A visual workflow indicator at the top of the tab shows the three stages of transfer approval:

1. Created

Transfer submitted

2. Pending Review

Awaiting confirmation

3. Confirmed

Stock updated

Approval Actions

Each pending transfer document has three available actions:

  • Review & Edit — Opens the confirmation modal where you can review all items, adjust quantities if needed, and confirm the transfer
  • Quick Confirm — Confirms the transfer with the original quantities without opening the review modal (useful when you trust the sent quantities match what was received)
  • Delete — Rejects and removes the pending transfer entirely
Step-Up Authentication Required: All approval actions (confirm, quick confirm, delete) require step-up authentication. You will be prompted to re-enter your password before the action is executed. This requires the confirm-warehouse-transfer permission.
Confirmation Modal

The Review & Edit button opens a confirmation modal that displays all items in the transfer. For each item, you can see the originally requested quantity and adjust the received quantity if different. This is particularly useful when:

  • Some items were damaged during transport and only a partial quantity was accepted
  • The sending department sent a different quantity than what was recorded
  • Items need to be redirected to a different department

After reviewing and optionally editing the quantities, click Confirm to finalize the transfer. The system will update stock balances in both the sending and receiving departments.

Department Access

The Approval tab filters transfers based on your department assignment. You only see transfers addressed to your department. Project administrators (system admins) can see and confirm all pending transfers regardless of department.

Creating a New Transfer

Click New Transfer in the page header to open the Transfer Book modal. This is a dual-panel form with header fields and a line items builder.

Line Items Builder

The bottom section of the Transfer Book is the line items builder. Search for items by name or code, enter quantities and prices, and add them to the transfer.

  • Item search — Autocomplete search across the warehouse nomenclature
  • Quantity — Number of units to transfer
  • Price — Unit price in GEL (used for cost tracking, not billing)
  • Total — Auto-calculated per line item
Insufficient Stock Check: When submitting a transfer, the system validates that the sending department has enough stock for each item. If a quantity exceeds available stock, the transfer is rejected with an error showing the item code, available quantity, and requested quantity.

3.3 Orders (Supply Requests)

Orders allow departments to formally request supplies from other departments. The requesting department submits a request specifying the required nomenclature and quantity, while the supplying department reviews, adjusts if necessary, and fulfills it. Orders create FHIR SupplyRequest resources and contain only quantity information — unlike transfers, no price tracking is involved.

Page Layout

The Orders page uses a 3-tab layout with two header action buttons:

  • Order History — Flat list of all order line items with edit/delete/correct actions
  • Analytics — One row per order document with KPI analytics and detail views
  • Needs Confirmation — Orders awaiting confirmation from the supplying department

Header action buttons:

  • Order Book — Opens the Order Book modal to create a new order with multiple items
  • Create Waybill — Creates a waybill (delivery document) from existing confirmed orders

Order History

The Order History tab shows every order line item individually, similar to the Transfer History tab. Each row is one item within an order document. Filters let you search by date range, document number, departments, and item name.

Orders vs. Transfers: Orders are quantity-only requests (no price). Once an order is confirmed and fulfilled, the actual movement of goods is recorded as a Transfer, which includes pricing information. Think of orders as the "request" and transfers as the "delivery."

Needs Confirmation

The Needs Confirmation tab shows orders awaiting confirmation from the supplying department. It follows the same approval workflow pattern as transfers, with a visual lifecycle indicator and step-up authentication for all actions.

Confirmation Actions
  • Review & Edit — Opens the confirmation modal where you can adjust the issued quantity for each item. This is the key difference from transfer approval: you can specify exactly how many units you are issuing, which may differ from the requested quantity.
  • Quick Confirm — Confirms the order with the original requested quantities (no adjustments)
  • Delete — Reject and delete the order with a confirmation dialog
Issued vs. Requested Quantity: When reviewing an order, each line item shows both the requested quantity (what the department asked for) and an editable issued quantity field (what you are actually sending). This allows partial fulfillment — for example, if 100 units were requested but only 80 are available, you can confirm with 80 and the requesting department will see the partial fulfillment.
Department Access

The Confirmation tab shows orders based on your role. Regular users see orders where their department is the receiver (supplier). Project administrators see all pending orders across all departments. The view-warehouse-orders permission is required to access this page.

3.4 FHIR Data Model Reference

All warehouse operations map to standard FHIR R4 resources with Georgian healthcare extensions. The table below summarizes the resource types, their key fields, and extension URLs used by each operation.

Operation FHIR Resource Key Fields Extensions
Receiving SupplyDelivery identifier, occurrenceDateTime, supplier, destination, suppliedItem admin-contract-number, package-quantity, package-price, admin-unit-price, admin-item-code, admin-item-name, admin-unit-of-measure, admin-line-total
Transfers SupplyDelivery identifier, occurrenceDateTime, supplier (from), destination (to), suppliedItem, status admin-unit-price, source-department, dest-department, transfer-workflow-status, transfer-approved-by-id, transfer-approved-by-name, transfer-approved-at; Identifier: transfer-document-number
Orders SupplyRequest identifier, authoredOn, status order-line-items, order-status, delivered-quantity, requester-department, receiver-department; Identifier: order-document-number
FHIR Base URL: All resource URLs use the base http://medimind.ge/fhir. Extension URLs follow the pattern http://medimind.ge/fhir/StructureDefinition/{extension-name}. The currency used for all monetary values is GEL (Georgian Lari).
