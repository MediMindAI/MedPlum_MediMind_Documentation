Warehouse Operations

The Warehouse module provides end-to-end supply chain management within MediMind. It covers six core operations: Receiving goods from suppliers, Transferring stock between departments, placing Orders for supplies, monitoring real-time Inventory balances, Writing off damaged or unusable stock, and submitting Procurement requests for new purchases. Each operation is accessible from the warehouse administration section and follows FHIR-compliant data storage.

ℹ️
FHIR Resources: Warehouse operations use three main FHIR resource types: SupplyDelivery (receipts and transfers), SupplyRequest (orders), and Basic (StockQuant inventory balances). All operations generate audit trail records for traceability.

3.1 Goods Receiving

The Receiving page manages incoming goods from external suppliers. Each receipt records the supplier, destination warehouse, and individual line items with quantities and pricing. Receipts follow a lifecycle from in-progress (being entered) to completed (confirmed and stocked).

View Modes

The page offers two tab views for organizing receipts:

  • List View -- Displays all receipts in a flat table sorted by date, with receipt number, supplier, warehouse, total amount, and status
  • Grouped View -- Groups receipts by document number, making it easy to see all line items belonging to a single delivery

Creating a Receipt

Click the Create Receipt button in the page header to open the receipt creation modal. The form is divided into a header section and a line items section:

Header Field Description FHIR Mapping
Date Receipt date (defaults to today) SupplyDelivery.occurrenceDateTime
Receipt Number Auto-generated unique identifier (read-only) SupplyDelivery.identifier
Company Supplier company (searchable dropdown from 495+ registered suppliers) SupplyDelivery.supplier (Organization reference)
Warehouse Destination department/warehouse that receives the goods SupplyDelivery.destination (Location reference)

Line Items

Each line item represents a product being received. The product entry row provides bidirectional search: type a product code or a product name and the system auto-completes the matching item from the warehouse catalog.

Line Item Field Description
Product Code Autocomplete from warehouse catalog; selecting a code auto-fills the name and unit
Product Name Autocomplete search (minimum 2 characters); selecting a name auto-fills the code and unit
Unit Measurement unit (auto-filled from catalog, editable)
Quantity Number of units received (minimum 1)
Unit Price Purchase price per unit
Unit Total Auto-calculated: Quantity x Unit Price (read-only)
Sale Price Retail/sale price per unit
Sale Total Auto-calculated: Quantity x Sale Price (read-only)

After filling in a line item, click the + button to add it to the receipt. Added items appear in a scrollable table below. Each item can be removed by clicking the trash icon. Click Save to finalize the receipt.

📦
RS Import: The Import from RS button allows importing receipts directly from the Revenue Service (RS) system, streamlining data entry for officially documented deliveries.

3.2 Transfers

The Transfers page manages movement of stock between departments (think of it like an internal shipping system). A transfer moves items from a source department to a destination department and requires approval before the stock is actually moved. This prevents unauthorized or accidental inventory changes.

View Modes

Three tabs organize transfers by different perspectives:

  • All Transfers -- Every transfer line item in a flat list, filterable by date, department, and status
  • Grouped View -- Transfers grouped by document number, showing the full picture of a multi-item transfer in one row
  • Pending Approval -- Only transfers awaiting confirmation, with an orange badge showing the count

Transfer Lifecycle

Transfers follow a controlled workflow to ensure accountability:

Status Description Who Acts
In-Progress Transfer created, awaiting confirmation by the receiving department Sender creates
Completed Transfer confirmed -- stock is moved from source to destination Receiver confirms
Abandoned Transfer rejected or cancelled Either party
Step-Up Authentication: Creating and confirming transfers requires step-up authentication (re-entering your password). This extra security step prevents unauthorized stock movements and creates an audit trail of who approved each transfer.

Creating a Transfer

Click New Transfer to open the Transfer Book modal. This dual-panel interface lets you select items from the source department's inventory and add them to the transfer:

Field Description FHIR Mapping
Date Transfer date (defaults to today) SupplyDelivery.occurrenceDateTime
Document Number Auto-generated transfer document identifier SupplyDelivery.identifier
From Department Source department (selecting this loads available inventory in the left panel) Extension: fromDepartment (Location reference)
To Department Destination department Extension: toDepartment (Location reference)
Direct Write-Off When enabled, skips the approval step and completes the transfer immediately Extension: directWriteOff

The left panel shows all items available in the source department. Click an item to move it to the right panel (selected items). Adjust quantities as needed. The system validates that requested quantities do not exceed available stock.

Transfer Approval

The Pending Approval tab shows transfers that need confirmation from the receiving department. The approval interface allows reviewing transfer details, editing quantities if needed, and confirming or deleting the transfer.

  • Department-based access -- Users only see transfers relevant to their assigned departments (admins see all)
  • Quantity editing -- The receiver can adjust quantities before confirming (e.g., if fewer items arrived than expected)
  • Stock validation -- The system checks that the source department still has sufficient stock before completing the transfer
  • Audit trail -- Confirmation creates a Provenance record linking the action to the authenticated user
🔄
FHIR Data: Transfers are stored as SupplyDelivery resources with type code transfer. Each line item is a separate resource, grouped by document number. Confirmation moves stock via the StockQuant service, decrementing the source and incrementing the destination.

3.3 Orders

The Orders page handles supply requests between departments. When a department needs supplies from a warehouse, they create an order specifying what they need and from which supplier/warehouse. Orders go through a confirmation workflow before being fulfilled.

View Modes

  • All Orders -- Complete list of all orders with status, date, requester, and receiver details
  • Grouped View -- Orders grouped by document number for multi-item orders
  • Confirmation Queue -- Orders in draft or active status awaiting processing (orange badge shows count)

Order Lifecycle

Status Description FHIR Status
Draft Order created but not yet submitted SupplyRequest.status = draft
Active Order submitted and awaiting fulfillment SupplyRequest.status = active
Complete Order fulfilled -- stock has been delivered SupplyRequest.status = completed
Cancelled Order cancelled before fulfillment SupplyRequest.status = cancelled

Creating an Order

Two options are available for creating orders:

  • Order Book -- A dual-panel interface similar to the Transfer Book. Select the requesting department and the supplier/receiver department, then pick items from the receiver's inventory
  • Create Waybill -- Creates a delivery waybill from existing confirmed orders, linking orders to actual shipments
Field Description FHIR Mapping
Date Order date SupplyRequest.authoredOn
Document Number Auto-generated or manual order number SupplyRequest.identifier
Requester Department The department placing the order SupplyRequest.requester (Location reference)
Receiver Department The warehouse/supplier fulfilling the order (selecting this loads available inventory) SupplyRequest.supplier (Location reference)
📋
Order Line Items: Each order can contain multiple line items. Line items are stored as a JSON extension on the SupplyRequest resource, including item code, name, unit, and quantity for each product.

3.4 Inventory & Stock

The Inventory page provides a real-time view of stock levels across all departments. It uses a materialized balance system called StockQuant -- think of it as a live ledger that updates instantly when goods are received, transferred, or consumed, instead of recalculating from the full transaction history each time.

Stock Levels Tab

The main inventory view displays a filterable table of all stock items. Each row represents a unique combination of product, location, lot number, and quality status.

Column Description
Code Product catalog code
Goods Product name
Type Item category/type
Quantity Current stock level; shows available/total breakdown when items are reserved; out-of-stock badge for zero quantity
Price Unit price
Total Total value (quantity x price)
Unit Measurement unit
Expiration Expiry date with color-coded badges: red (expired), orange (expiring soon), yellow (within warning period)
Series/Lot Lot/batch number with quality status badge (quarantine in yellow, rejected in red)

Filters

The filter panel provides multiple ways to narrow down inventory:

  • Department -- Select a specific warehouse or department to view its stock
  • Item Group -- Filter by product category
  • Quantity checkboxes -- Show/hide zero balances, non-zero balances, or negative balances
  • Grouped view -- Aggregate quantities across lots for the same product
  • Stock Status -- Quick filter for All, Low Stock, Out of Stock, Expiring, or Expired items
  • Zone -- Filter by warehouse zone (Cold Chain, Controlled, Hazmat, General)
  • Cross-Location Search -- Search for a product across all departments to find where it is in stock

The table supports inline search by product code and name, price range filtering, and expiration date range filtering. Results are paginated (50 items per page) and can be exported to Excel.

📊
Transaction History: Click any row in the balance table to open the transaction history modal, which shows all stock movements (receipts, transfers, adjustments) that contributed to the current balance for that specific item and location.

Picking Queue (FEFO)

The Picking Queue tab shows approved transfers that need to be physically fulfilled. When a transfer is approved, it appears here as a pick request. The system uses FEFO (First Expired, First Out) logic to recommend which lot to pick from -- items closest to their expiration date are suggested first.

The picking workflow operates in two stages:

  1. Select a transfer request -- Choose from the list of pending transfer cards. Each card shows the item name, source/destination departments, quantity needed, and status
  2. Pick from lots -- The system queries StockQuant records for the source department and displays available lots sorted by expiration date (earliest first). The first lot is marked as the FEFO recommendation
Pick List Column Description
Product Code / Name The product being picked
Bin Location Physical storage location within the warehouse
Lot Number Batch/lot identifier for traceability
Expiration Date Lot expiry date (FEFO sorting key)
Quantity Requested How many units the transfer needs
Suggested Pick FEFO-recommended quantity from this lot (capped at available stock)
Confirmed Pick Actual quantity picked by the warehouse operator
FEFO Override: If you need to pick from a different lot than the FEFO recommendation (for example, if a closer lot has packaging damage), you can override the suggestion. The system will ask you to provide a reason for the override, which is recorded for audit purposes.
🔍
StockQuant Data Model: Each StockQuant record is a FHIR Basic resource with a composite key of itemCode | locationId | lotNumber | qualityStatus. This provides O(1) balance lookups instead of recalculating from the full transaction history. Quality statuses include: accepted (available for use), quarantine (under inspection), and rejected (not usable).

3.5 Write-offs

The Write-offs page handles removal of damaged, expired, or otherwise unusable stock from inventory. When items cannot be sold or used (for example, expired medications or broken equipment), a write-off document formally removes them from the system and updates stock balances accordingly.

View Modes

The page organizes write-offs across three tabs:

  • History -- All write-off documents in a flat table sorted by date, with document number, department, reason, total value, and status
  • Analytics -- Write-offs grouped by document number, providing a consolidated view of multi-item write-offs
  • Pending Confirmation -- Write-offs awaiting approval before being finalized, with an orange badge showing the count

Table Columns

Column Description
Document Number Unique identifier for the write-off document
Date Date the write-off was created
Department The warehouse or department from which stock is being removed
Reason Reason for write-off (expiry, damage, quality failure, etc.)
Total Value Combined value of all written-off items
Status Current status badge (in-progress, completed, or abandoned)

Write-off Lifecycle

Status Description Who Acts
In-Progress Write-off created, awaiting confirmation from an authorized user Creator submits
Completed Write-off approved -- stock is permanently removed from balances Approver confirms
Abandoned Write-off rejected or cancelled before completion Either party

Creating a Write-off

Click the Create Write-off button to open the write-off creation modal. The form uses a dual-panel layout: select items from the department's current inventory on the left, then adjust quantities and provide a reason on the right.

Field Description FHIR Mapping
Date Write-off date (defaults to today) SupplyDelivery.occurrenceDateTime
Document Number Auto-generated unique identifier SupplyDelivery.identifier
Department Source department from which items are being written off Extension: fromDepartment (Location reference)
Reason Reason for the write-off (free text or predefined category) Extension: writeOffReason

Analytics View

The Analytics tab groups write-offs by document number, providing a summary view that shows the total items and value for each write-off document. This is useful for auditing and reporting on stock losses over time.

Pending Confirmation

The Pending Confirmation tab shows write-offs that require approval from an authorized user before stock is actually removed. This approval step ensures that write-offs are reviewed before permanently affecting inventory balances.

🗑
FHIR Data: Write-offs are stored as SupplyDelivery resources with type code write-off. Each line item is a separate resource, grouped by document number. Confirmation permanently decrements the StockQuant balance for the source department.

3.6 Procurement

The Procurement page manages purchase requests for new stock. When a warehouse needs to buy supplies from external vendors, a procurement request is submitted specifying the items, quantities, and priority level. Requests go through a multi-step approval workflow before being sent to suppliers.

View Modes

The page organizes procurement requests across three tabs:

  • Request History -- All procurement requests in a table with request number, date, requester, priority, status, and total value
  • Analytics -- Requests grouped for summary reporting and spend analysis
  • Pending Approval -- Requests awaiting review and authorization, with an orange badge showing the count

Table Columns

Column Description
Request Number Unique procurement request identifier
Date Date the request was submitted
Requester Department or user who initiated the request
Priority Request urgency level with color-coded badge (normal, urgent, critical)
Status Current workflow status
Total Value Estimated total cost of requested items

Priority Levels

Priority Description FHIR Value
Normal Standard procurement timeline SupplyRequest.priority = routine
Urgent Expedited processing required SupplyRequest.priority = urgent
Critical Immediate action needed -- stock-out risk SupplyRequest.priority = stat

Procurement Lifecycle

Status Description FHIR Status
Draft Request created but not yet submitted SupplyRequest.status = draft
Submitted Request sent for approval SupplyRequest.status = active
Under Review Being evaluated by approving authority Extension: underReview
Approved Authorized for purchase Extension: approved
Ordered Purchase order sent to supplier Extension: ordered
Received Goods delivered and received into inventory SupplyRequest.status = completed
Cancelled Request cancelled at any stage SupplyRequest.status = cancelled

Creating a Procurement Request

Click the New Request button to open the procurement creation modal. The form includes header fields for request metadata and a line items section for specifying products and quantities.

Field Description FHIR Mapping
Date Request date (defaults to today) SupplyRequest.authoredOn
Request Number Auto-generated unique identifier SupplyRequest.identifier
Requester Department submitting the procurement request SupplyRequest.requester (Location reference)
Priority Urgency level (normal, urgent, critical) SupplyRequest.priority
Supplier Target vendor for the purchase (optional at creation) SupplyRequest.supplier (Organization reference)

Pending Approval

The Pending Approval tab shows procurement requests awaiting authorization. Approvers can review request details, adjust quantities if needed, and approve or reject the request.

Request Detail View

Click any row in the request history to open a read-only detail modal. This shows the complete request information including all line items, approval history, and current status.

🛒
FHIR Data: Procurement requests are stored as SupplyRequest resources with a request-type extension set to purchase-request. Line items are stored as a JSON extension, and the approval workflow is tracked via status extensions and Provenance records.
