Procurement Overview

The Procurement module lets departments submit purchase requests for items that are not currently available in the warehouse. It provides a complete workflow from request creation through approval or rejection, with built-in analytics and permission-based access control.

Think of it as a formal "shopping list" system: a department describes what it needs, a manager reviews and approves (or rejects) the request, and the warehouse team can then fulfill the order.

Page Layout

The procurement page follows the unified warehouse layout pattern with a page header and three switchable tabs:

Tab Icon Purpose
Request History List Browse, filter, and search all purchase requests with sorting and pagination
Analytics Chart KPI summary strip, department activity, priority breakdown, and status distribution
Pending Approval Clipboard Queue of requests waiting for review, with approve and reject actions

Each tab shows a badge count in its header. The History and Analytics tabs display the total number of requests, while the Pending Approval tab shows only the count of requests awaiting action. The page header also includes a New Purchase Request button that opens the creation form.

Tab Persistence: Your last active tab is remembered in the browser, so when you return to the procurement page it opens to the same tab you were on before.

Status Lifecycle

Every purchase request moves through a series of statuses. The status badges are color-coded so you can quickly scan a list and see what needs attention:

Status Badge Color Meaning
Draft Gray Request created but not yet submitted
Submitted Blue Request sent for approval; appears in the Pending Approval queue
Under Review Violet An approver has opened the request and is evaluating it
Approved Teal Request approved and ready for the warehouse to act on
Rejected Red Request denied; a reason is attached by the reviewer
Ordered Indigo Items have been ordered from a supplier
Partially Received Orange Some items have arrived, but the order is not yet complete
Received Green All requested items have been received into the warehouse
Cancelled Gray Request was cancelled before completion
Deletion Restriction: Only requests in Submitted status can be deleted. Once a request has been approved, ordered, or rejected, it becomes part of the permanent audit trail and cannot be removed.

Creating a Purchase Request

To request new supplies, click the New Purchase Request button in the page header. A modal form opens with four organized sections.

Section 1: Request Details

The top section captures the essential information about the request:

Field Required Description
Date Yes Request date. Defaults to today and uses a date picker
Document Number Auto Auto-generated in the format PR-YYYY-NNN (e.g., PR-2026-015). Read-only
Requesting Department Yes The department that needs the items. Searchable dropdown listing all inventory departments
Target Department Yes The warehouse or department that will handle the purchase. Searchable dropdown
Priority Yes A three-level segmented control: Normal (blue), Urgent (orange), or Critical (red). Defaults to Normal

Section 2: Justification

An optional text area where you explain why these items are needed. While not required by the system, providing a clear justification helps approvers make faster decisions. The field auto-sizes between 3 and 5 lines as you type.

Section 3: Line Items

This is where you list the actual items you need. The form starts with one empty row and you can add more with the Add Item button.

Column Description
# Row number (automatic)
Item Description Free-text description of what you need. The item does not need to exist in the warehouse catalog
Quantity Number of units needed (minimum 1)
Unit Unit of measure selected from a dropdown: piece, box, ampoule, tablet, vial, set, liter, package, pair, meter, gram, dose, or ml
Delete Remove this line (disabled when only one row remains)
Free-Text Items: Unlike warehouse transfers and orders which pick from the existing product catalog, procurement items are described in free text. This is because purchase requests are typically for items that do not yet exist in the system.

Section 4: Attachments

Optionally attach supporting documents such as supplier quotes, specification sheets, or approval letters. Supported file types include PDF, Word, Excel, and images (PNG/JPG). Multiple files can be attached to a single request.

Unsaved Changes Protection

If you start filling in items and then try to close the modal, the system will ask for confirmation before discarding your work. This prevents accidental loss of partially completed requests.

Request History Tab

The Request History tab shows all procurement requests in a sortable, paginated table.

Filter Panel

A collapsible filter section at the top lets you narrow down the list:

Filter Type Description
Date From / To Date picker Filter requests by date range
Department Searchable dropdown Show requests from a specific department
Warehouse Group Searchable dropdown Filter by product category
Status Dropdown Show only requests with a specific status (Draft, Submitted, Approved, etc.)
Priority Dropdown Filter by Normal, Urgent, or Critical priority
General Search Text input Search across document numbers, department names, justification text, and item descriptions

The filter panel shows an active filter count badge so you know how many filters are currently applied. Use the Clear button to reset all filters at once.

Table Columns

The request table displays the following columns on desktop:

Column Sortable Description
Date Yes Request creation date
Document Number No Unique identifier in PR-YYYY-NNN format
Department Yes Requesting department name
Priority No Color-coded badge (blue/orange/red)
Items No Number of line items in the request
Estimated Total Yes Estimated cost in GEL
Status No Current status badge

Click any row to open a detail modal showing the full request information, including all line items, justification text, review notes, and attachments. A delete action is available on each row for requests still in Submitted status.

The table supports pagination with configurable page sizes (10, 20, 50, or 100 rows). A summary footer shows the total request count and combined estimated value.

Mobile View: On screens narrower than 768px, the table is replaced with compact cards showing the document number, date, status badge, department, priority, item count, and estimated total. All the same data, just reorganized for smaller screens.

Analytics Tab

The Analytics tab provides a bird's-eye view of procurement activity. It starts with a KPI summary strip followed by three collapsible analysis sections.

KPI Summary Strip

Three key metrics displayed as prominent cards at the top:

Total All Requests
Pending Awaiting Review

Department Activity

Horizontal bar chart showing which departments submit the most purchase requests, along with the total estimated value per department. Bars are sized proportionally so the most active department fills the full width.

Priority Distribution

Horizontal bar chart breaking down requests by priority level. Each bar is color-coded to match its priority (blue for Normal, orange for Urgent, red for Critical), giving you a quick sense of how many urgent requests exist.

A summary table listing each status with its color-coded badge and the number of requests currently in that status. Useful for identifying bottlenecks (e.g., many requests stuck in "Under Review").

Approval Workflow

The Pending Approval tab is where authorized staff review purchase requests and decide whether to approve or reject them. Each pending request appears as an expandable card with all the details needed to make a decision.

Approval Card

Each card in the approval queue has the following layout:

Section Content
Header Bar Gradient-colored bar showing the document number, date, priority badge, and status badge
Info Row Requesting department, target department (with arrow indicator), requester name, and item count
Justification The requester's explanation for why these items are needed (if provided)
Items Table Expandable/collapsible list of all line items with description, quantity, and unit columns
Action Buttons Approve (green) and Reject (red) buttons at the bottom of the card

Approving a Request

To approve a request:

  1. Review the request details, justification, and line items on the approval card
  2. Click the green Approve button
  3. A step-up authentication dialog appears asking you to re-enter your password
  4. After successful authentication, the request status changes to Approved
  5. The requesting department is automatically notified of the approval

Rejecting a Request

To reject a request:

  1. Click the red Reject button on the approval card
  2. A rejection reason text area expands below the action buttons
  3. Enter a clear reason for the rejection (required, cannot be empty)
  4. Click Reject again to confirm, or Cancel to go back
  5. A step-up authentication dialog appears asking you to re-enter your password
  6. After successful authentication, the request status changes to Rejected and the reason is saved
  7. The requesting department receives a notification with the rejection reason
Step-Up Authentication: Both approve and reject actions require you to re-enter your password. This is a security measure that prevents unauthorized approvals, even if someone gains access to an already-logged-in session.

Permission Requirements

Not everyone can approve or reject procurement requests. The system checks two conditions:

  • Permission Code: The user must have the approve-procurement permission assigned to their role, OR be a system administrator
  • Department Access: The user must belong to the target department (the warehouse that will handle the purchase). This prevents staff from one warehouse approving requests meant for another

If a user does not have the required permissions, the Approve and Reject buttons are hidden from the approval cards. They can still view the pending requests, but cannot act on them.

Empty Approval Queue

When no requests are waiting for approval, the tab displays a friendly empty state message instead of an empty list. This confirms that all pending requests have been processed.

Automatic Notifications

The procurement system sends notifications at key points in the workflow:

Event Who Gets Notified
Request Submitted Department managers of the target department
Request Approved The requester and the requesting department
Request Rejected The requester and the requesting department (includes rejection reason)

FHIR Data Model

For integration teams, procurement requests are stored as SupplyRequest FHIR R4 resources, distinguished from regular stock orders by a request-type extension set to purchase-request.

Data Field FHIR Path / Extension
Document Number SupplyRequest.identifier (system: procurement-document-number)
Request Date SupplyRequest.authoredOn
FHIR Status SupplyRequest.status (draft | active | completed | cancelled)
Extended Status Extension: purchase-approval-status (9 values listed above)
Priority SupplyRequest.priority (routine | urgent | stat) + Extension: purchase-priority
Requesting Department Extensions: requester-department (ID), requester-department-name
Target Department Extensions: receiver-department (ID), receiver-department-name
Justification Extension: purchase-justification
Line Items Extension: purchase-line-items (JSON array of description, quantity, unit)
Estimated Cost Extension: purchase-estimated-cost (decimal, GEL)
Requester Name Extension: purchase-requester-name
Review Notes Extension: purchase-review-notes
Total Quantity SupplyRequest.quantity.value (sum of all line item quantities)
Extended vs. FHIR Status: FHIR SupplyRequest only supports a limited set of statuses (draft, active, completed, cancelled). The procurement module uses a custom purchase-approval-status extension to track the full 9-stage lifecycle, while mapping to the closest standard FHIR status for interoperability.
