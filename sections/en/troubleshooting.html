Troubleshooting

This section covers common issues you may encounter while using the patient registration module and their solutions.

Common Issues

Quick Tip: Most registration issues are related to validation rules or required fields. Check the form for red error indicators before submitting.
Patient Not Found by Personal ID

Problem: Searching for a patient by personal ID returns no results, even though the patient should exist in the system.

Possible Causes:

  • Personal ID format is incorrect (must be exactly 11 digits)
  • Personal ID entered does not pass Luhn checksum validation
  • Patient was registered with a different ID or as an unknown patient
  • Patient record exists but with typos in the ID field

Solution:

  1. Verify Personal ID Format: Georgian personal IDs must be exactly 11 digits. Remove any spaces or hyphens.
  2. Check Luhn Algorithm: The system validates the checksum. Use a valid Georgian personal ID.
  3. Try Alternative Search: Use the advanced search filters to search by name, birth date, or phone number.
  4. Check Unknown Patients: If the patient was registered in an emergency, they may have a temporary system-generated ID.
Note: The auto-search triggers only after entering exactly 11 digits. If you enter fewer or more digits, the search will not execute.
Form Validation Errors

Problem: The registration form displays validation errors and prevents submission.

Common Validation Issues:

Field Validation Rule Solution
First Name Required (unless Unknown Patient) Enter patient's first name or enable "Unknown Patient" toggle
Personal ID 11 digits with Luhn checksum Enter valid 11-digit Georgian personal ID
Birth Date Cannot be in the future Select a valid past date
Phone International format required Include country code (e.g., +995)
Guardian Info Required for patients under 18 Fill all guardian fields for minors
Department Must match visit type Select a department filtered by the chosen visit type

Solution:

  1. Scroll through the form and look for fields highlighted in red.
  2. Review error messages displayed below invalid fields.
  3. Correct all validation errors before attempting to submit again.
Active Visit Warning

Problem: When selecting a patient, a warning appears: "Patient has an active visit."

Cause: The system detects an existing Encounter resource with status='in-progress' for this patient. FHIR best practices discourage creating multiple active visits simultaneously.

Solution:

  1. Verify Active Visit: Check if the patient is currently receiving care in another department.
  2. Close Previous Visit: If the previous visit has ended, close it in the system first.
  3. Override Warning: If creating a new visit is medically necessary (e.g., emergency), you may proceed by clicking "Continue Anyway" in the modal.
  4. Contact IT Support: If the warning appears incorrectly, the previous Encounter may need administrative correction.
Important: Creating duplicate active visits can cause data integrity issues. Always verify before overriding this warning.
Draft Not Saving or Recovering

Problem: Form drafts are not auto-saving, or previously saved drafts are not loading when returning to the registration page.

Possible Causes:

  • Browser localStorage is disabled or full
  • Incognito/private browsing mode is active
  • Browser cache has been cleared
  • Different browser or device being used
  • Draft exceeded localStorage size limit (typically 5-10MB)

Solution:

  1. Check Browser Settings: Enable localStorage in your browser privacy settings.
  2. Avoid Private Mode: Use a regular browser window for registration tasks.
  3. Clear Old Drafts: If localStorage is full, manually delete old drafts from the draft recovery modal.
  4. Use Same Device: Drafts are stored locally and do not sync across devices.
  5. Submit Regularly: Don't rely solely on auto-save—submit registrations when complete.
Auto-Save Frequency: Drafts are saved automatically after 1 second of inactivity. Look for the "Draft Saved" indicator at the top of the form.
Insurance Section Not Visible

Problem: The Insurance section is collapsed or grayed out and cannot be filled in.

Cause: The Insurance section is only enabled when the "Create Visit" toggle in the Registration section is turned ON. Without a visit, insurance information cannot be linked to an Encounter.

Solution:

  1. Scroll to the Registration section.
  2. Find the "Create Visit" toggle switch.
  3. Toggle it to ON.
  4. The Insurance section will become active and editable.

FHIR Context: Insurance is stored as a Coverage resource linked to an Encounter. No visit means no Coverage can be created.

Department Dropdown is Empty

Problem: The Department dropdown in the Registration section shows no options.

Cause: Departments are dynamically filtered based on the selected Visit Type. If no visit type is selected, or no departments match the selected type, the dropdown will be empty.

Solution:

  1. Ensure you have selected a Visit Type (Ambulatory, Stationary, or Emergency).
  2. Wait for the dropdown to reload with filtered departments.
  3. If still empty, contact IT—departments may need to be configured for this visit type.
Note: The department list is filtered by the useDepartments hook based on the selected visit type. Ensure visit types are correctly mapped in the system configuration.
Mobile Wizard Not Advancing

Problem: On mobile devices, the step wizard does not advance to the next step, or the "Next" button is disabled.

Possible Causes:

  • Required fields in the current step are not filled
  • Validation errors exist in the current step
  • JavaScript error in the mobile view

Solution:

  1. Check for validation errors in the current step (red fields or error messages).
  2. Ensure all required fields are completed.
  3. Scroll through the step to verify all sections are visible and filled.
  4. If the issue persists, try switching to desktop view or refreshing the page.
Mobile Limitation: Some complex form interactions work better on desktop. For intensive registration tasks, consider using a desktop or tablet device.

Error Codes

The registration system uses FHIR OperationOutcome resources to communicate errors. Below are common error codes you may encounter:

FHIR OperationOutcome Error Codes

Code Severity Description Action
invalid Error Resource content is invalid Check field formats and required fields
structure Error Structural issue with FHIR resource Contact IT support—data binding issue
required Error Required field is missing Fill in the indicated required field
value Error Value is outside allowed range Check date ranges, numeric limits, or enum values
invariant Error Business rule violation Review business logic (e.g., guardian required for minors)
security Error Authorization failed Check user permissions or re-authenticate
login Error Session expired Log in again
conflict Error Resource conflict (e.g., duplicate) Check for existing patient records or active visits
transient Warning Temporary server issue Retry the operation
informational Information Informational message No action needed

Form Validation Messages

In addition to FHIR errors, the registration form displays client-side validation messages:

Message Trigger Fix
"Personal ID must be 11 digits" Personal ID length ≠ 11 Enter exactly 11 digits
"Invalid Personal ID checksum" Luhn algorithm validation fails Use a valid Georgian personal ID
"First name is required" First name empty and "Unknown Patient" is OFF Fill first name or enable "Unknown Patient"
"Guardian information required for minors" Patient age < 18 and guardian fields empty Fill all guardian fields
"Phone number format invalid" Phone missing country code Include country code (e.g., +995)
"Birth date cannot be in the future" Birth date > today Select a past date
"Department is required" Visit type selected but no department Select a department from the dropdown
Need More Help? If you encounter an error not listed here, contact your IT support team with the exact error message and the steps you were performing.
