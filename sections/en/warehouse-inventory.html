Stock Levels

The Stock Levels tab provides a real-time view of current inventory balances across all hospital departments. Think of it as a live spreadsheet that always reflects the latest stock position -- every receipt, transfer, and write-off updates the numbers automatically.

9 Table Columns
50 Items Per Page
4 Warehouse Zones
30s Cache Duration

Filter Panel

The filter panel at the top lets you narrow down the balance view to exactly the items you need. Filters are arranged in two rows:

Row 1 -- Primary Filters:

  • Date -- View balances as of a specific date (defaults to today)
  • Department -- Select a specific department (searchable dropdown). When empty, shows all departments
  • Group -- Filter by item type/group (e.g., Medications, Consumables)
  • Warehouse Group -- Filter by top-level warehouse category

Row 2 -- Stock Filters: A visual strip of checkboxes for quick stock status filtering:

  • Show Zeros -- Include items with zero quantity (out of stock)
  • Show Non-Zeros -- Include items with positive stock (enabled by default)
  • Show Negative -- Include items with negative balance anomalies (data discrepancies)
  • Grouped -- Collapse multiple batches of the same item into expandable group rows
Zone Filtering: An optional zone segmented control lets you filter by storage zone: Cold Chain, Controlled, Hazmat, or General. This is useful for warehouse staff managing temperature-sensitive or restricted items.

Table Columns

The balance table shows one row per stock line (item + lot combination). When Grouped mode is enabled, items with multiple batches are collapsed under an expandable header showing the aggregate totals.

Inline Search & Export

Above the table rows, a compact filter bar provides quick search across loaded data:

  • Code Search -- Filter by item code
  • Name Search -- Filter by item name (partial match)
  • Price Range -- Filter by minimum and maximum unit price
  • Expiration Range -- Filter by expiry date window using date pickers
  • Excel Export -- One-click export of all visible data to a spreadsheet file
  • Refresh -- Manually reload data from the server (bypasses the 30-second cache)
Keyboard Shortcut: Press Enter in any search field to immediately apply all filters.

FHIR Data Model

Stock balances are stored as Basic resources with the code stock-quant. Each StockQuant record represents a unique combination of item, location, lot number, and quality status.

Concept FHIR Resource Key Extension
Stock Balance Basic (code: stock-quant) sq-quantity, sq-unit-cost, sq-expiry-date
Location Location / Organization sq-location-id, sq-location-name
Item Master DeviceDefinition sq-item-code, sq-item-name
Lot Tracking Basic (stock-quant) sq-lot-number, sq-quality-status
Reserved Qty Basic (stock-quant) sq-reserved-qty
Composite Key: Each StockQuant is uniquely identified by the combination of itemCode | locationId | lotNumber | qualityStatus. Items without lot tracking use "NONE" as the lot number.

Picking Queue

The Picking Queue is where warehouse staff fulfill approved transfer requests. When a department-to-department transfer is approved, it appears here as a "pending request" card. The picker selects a request, views the pick list, and confirms the quantities they actually pick from the shelves.

Picking Workflow

The picking process follows three steps:

1. Select Request

Choose a pending transfer from the request list

Shows item name, source/destination departments, quantity, and status

2. Pick Items

View the pick list with FEFO-recommended lots

Enter confirmed quantities and scan barcodes

3. Confirm

Submit confirmed picks

Stock is deducted from source and added to destination

Pending Request Cards

Each approved transfer request appears as a clickable card showing:

  • Item Name -- The product being requested
  • Route -- Source department arrow destination department
  • Quantity -- Amount requested with unit of measure (shown in a blue badge)
  • Status Badge -- "In Progress" for active requests

Click a card to load its pick list. The selected card gets a blue left border and shadow to indicate it is active.

Pick List Table

When a request is selected, the system queries real stock data (StockQuant records) for the source department and builds a pick list sorted by the FEFO (First-Expiry-First-Out) principle -- lots expiring soonest appear first.

Column Description

Product Code Item code in monospace font for easy reading
Product Name Item name. Shows a green "FEFO Recommended" badge on the lot the system recommends picking first
Bin Location Physical storage location in the warehouse

FEFO -- First-Expiry-First-Out

The FEFO system ensures that items closest to their expiration date are picked first, reducing waste. Here is how it works:

  • The system automatically sorts available lots by expiry date (earliest first)
  • The first lot in the sorted list gets the green "FEFO Recommended" badge
  • Expired and quarantined lots are sorted to the bottom of the list but remain visible for awareness
  • Lots without an expiry date sort to the bottom (picked last)
FEFO Override: If a picker selects a lot that is NOT the FEFO-recommended one, the system opens an override modal requiring a reason. Available reasons: damaged packaging, customer request, lot recall, insufficient quantity, quality issue, or other (with free-text notes). The override reason and optional notes are logged for audit purposes.

Zone Grouping

Pick list items are grouped by warehouse storage zone, so the picker can work through one zone at a time instead of walking back and forth across the warehouse. Each zone has a collapsible header:

Zone Icon Description
Cold Chain Snowflake (blue) Temperature-controlled items (vaccines, biologics)
Controlled Lock (red) Restricted access items (narcotics, controlled substances)
Hazmat Biohazard (orange) Hazardous materials requiring special handling
General Package (gray) Standard storage items (most consumables and medications)

Barcode Scanning

The pick list includes a barcode scanner input field at the top. When a barcode is scanned (or typed and Enter is pressed):

  • The system searches for a matching item by barcode or product code
  • If found, the matching row is highlighted with a visual pulse and the quantity input receives focus
  • An audio beep confirms the scan: high tone for success, low tone for no match
  • The highlight clears automatically after 3 seconds

Progress Tracking

A progress bar in the header shows the overall pick completion. Fully picked items count as 100%, partially picked as 50%. The progress percentage updates in real time as the picker confirms quantities.

Write-Offs

Navigation Note: Write-Offs is accessed as a separate page via its own menu item in the Warehouse sidebar, not as a tab within the Inventory page. The Inventory page contains only the Stock Levels and Picking Queue tabs.

Write-offs remove items from inventory when they can no longer be used -- expired medications, damaged supplies, missing stock discovered during audits, or items recalled by the manufacturer. The write-off module provides a complete audit trail from creation through approval.

The page has a "New Write-Off" button in the header and three tabs:

3 Tabs
5 KPI Cards
4 Analytics Sections

Write-Off History Tab

The Write-Off History tab shows a sortable, paginated list of all write-off line items. Each row represents a single item that was written off.

Filters

Filter controls above the table let you narrow down the history:

  • Date Range -- Filter by start and end date
  • Department -- Filter by department (searchable dropdown)
  • Document Number -- Search by specific document number
  • Warehouse Group -- Filter by product category
  • Item Search -- Search by item name or code

A summary footer below the table shows the total record count and the total monetary value of all visible write-offs in red.

Correction: Completed write-offs can be corrected by clicking the adjustment icon on the row. This opens a correction modal that creates a reverse stock movement to undo the write-off.

Analytics Tab

The Analytics tab provides a rich overview of write-off activity with KPI cards, visual charts, and a grouped document table.

  • Department Activity -- Horizontal bar chart showing write-off counts per department, making it easy to spot departments with unusually high write-off volumes
  • Reason Distribution -- Horizontal bar chart showing the count and value for each write-off reason category
  • Period Summary -- Table with weekly or monthly toggles showing document counts and total values over time

Below the analytics, a filter bar and grouped document table let you browse individual write-off documents with their aggregated totals.

Creating a Write-Off

Click the "New Write-Off" button in the page header to open the creation modal. The modal uses a dual-panel layout (the same pattern used for transfers and orders):

Header Fields

Field Required Description
Date Yes Write-off date (defaults to today)
Document Number No Auto-generated (WO-timestamp format). Cannot be edited manually
Department Yes The department from which stock will be removed. Selecting a department loads its available inventory in the left panel
Reason Yes Free-text explanation for the write-off (e.g., "Expired medication batch 2024-03"). Must be filled before submission

Dual-Panel Item Selection

Left Panel -- Available Stock

Shows items currently in stock at the selected department

Searchable/filterable list

Click an item to move it to the right panel

Right Panel -- Selected Items

Items selected for write-off

Editable quantity for each item (cannot exceed stock)

Running total shown at the bottom

Step-Up Authentication: Submitting a write-off requires password re-entry (step-up auth) to prevent accidental or unauthorized stock removal. This is the same security pattern used across all warehouse operations that modify stock levels.

Validation Rules

  • At least one item must be selected
  • Each item quantity must be greater than zero and not exceed current stock
  • Reason field must not be empty
  • Department must be selected before items can be added
  • Closing the modal with unsaved items triggers a confirmation dialog

Approval Workflow

The Pending Confirmation tab shows write-offs that are awaiting approval. Documents are grouped by document number, and each group can be expanded to see individual line items.

Approval Table Columns

Column Description

Document Number Write-off document identifier
Department Department where stock will be removed
Item Count Number of line items in the document (blue badge)
Total Quantity Sum of all item quantities

Actions Confirm (green) and Reject (red) buttons

Confirm and Reject

  • Confirm -- Approves the write-off. Stock is permanently removed. Requires step-up authentication (password re-entry)
  • Reject -- Opens a modal where the reviewer can enter an optional rejection reason. The write-off is cancelled and stock remains unchanged. Also requires step-up authentication
Permission Required: The Confirm and Reject buttons are only active for users with the confirm-write-off permission or administrators. Users without this permission see disabled buttons.

Expanded Detail View

When a document row is expanded, a sub-table shows each line item with columns for Item Name, Unit, Quantity, Price, Total, and Reason. This allows the reviewer to examine every item before making an approval decision.

FHIR Data Model

Write-offs are stored as SupplyDelivery resources with a type code of write-off. Each line item is a separate SupplyDelivery resource, grouped by a shared document number identifier.

Field FHIR Path Description
Document Number SupplyDelivery.identifier Groups multiple line items into one document
Department SupplyDelivery.supplier Reference to Location/Organization resource
Item SupplyDelivery.suppliedItem.itemCodeableConcept CodeableConcept with item code and name
Quantity SupplyDelivery.suppliedItem.quantity Amount being written off
Price SupplyDelivery.extension (unit-price) Unit cost at time of write-off
Reason SupplyDelivery.extension (reason) Free-text write-off justification
Status SupplyDelivery.status in-progress (pending), completed (approved), abandoned (rejected)
Stock Impact: When a write-off is confirmed, the system decrements the corresponding StockQuant record and invalidates the balance cache. The stock change propagates immediately to the Stock Levels tab and any other view that reads inventory data.
