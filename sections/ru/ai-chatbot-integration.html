AI-чатбот — IT Интеграция

Этот раздел охватывает техническую архитектуру AI медицинского чатбота для IT-администраторов: модель данных FHIR, AI-сервисы, голосовые сервисы и безопасность.

Высокоуровневая архитектура

Чатбот соединяет React-фронтенд с внешними AI-сервисами через Supabase Edge Functions, с FHIR-основанным сохранением данных через Medplum.

flowchart LR A[React Frontend] -->|SSE Request| B[Flowise AI] A -->|Edge Functions| C[Supabase] A -->|FHIR API| D[Medplum Server] B --> E[Knowledge Bases] B --> F[LLM Models] C --> G[STT Services] C --> H[OCR Services]

Модель данных FHIR

AI-чатбот использует ресурсы FHIR R4 для сохранения данных. Все пользовательские расширения следуют шаблону: http://medimind.ge/fhir/StructureDefinition/{name}

Ресурсы FHIR

Ресурс Назначение Ключевые расширения
Communication Метаданные разговора session-id, knowledge-base, specialty, type, message-count
DocumentReference Случаи пациентов, документы пользователей anonymized-info, category, tags, vector-store-file-id
Binary Хранение файлов документов N/A
Practitioner Ссылка на векторное хранилище пользователя user-vector-store

Сохранение данных

Чатбот использует гибридный подход FHIR + локальное хранилище для оптимальной производительности:

flowchart TD A[User Action] --> B[Update UI State] B --> C[Save Locally] C --> D[Save to FHIR] D --> E{Success?} E -->|Yes| F[Complete] E -->|No| G[Fallback to Local Storage] G --> F style C fill:#f59e0b,stroke:#d97706,color:#000 style D fill:#10b981,stroke:#059669,color:#fff
Преимущества: Мгновенные обновления UI без ожидания ответа сервера, офлайн-возможности, кросс-устройственная синхронизация через FHIR, данные сохраняются после очистки браузера.

AI-сервисы

Доступ ко всем AI-сервисам осуществляется через Supabase Edge Functions или прямые вызовы Flowise API. Фронтенд никогда не взаимодействует напрямую с API AI-провайдеров.

Надёжность и безопасность

Обработка ошибок и устойчивость

Сервис Макс. попыток Backoff Таймаут
Flowise SSE 3 Экспоненциальный (1s, 2s, 4s) 180s
Enagram STT 2 Фиксированный (1s) 30s
Google STT 2 Фиксированный (1s) 30s
Чатбот для пациентов 2 Фиксированный (1s) 30s
Gemini OCR 1 Нет 30s
Цепочка резервных вариантов:
  1. Потоковая передача не удалась — 3 повторных попытки с backoff, затем переход на стандартный JSON-ответ
  2. OCR не удался — Клиентский OCR не удался, переход на облачный AI vision
  3. STT не удался — Отображение уведомления, ручной ввод текста
  4. FHIR не удался — Сохранение локально, фоновая синхронизация при следующей загрузке

Безопасность

Проблема Решение
Раскрытие API-ключей Все ключи хранятся в серверных секретах, никогда в коде фронтенда
Данные пациента в AI-промптах Контекст пациента использует анонимизированные сводки (возрастные диапазоны, без PII)
CORS Edge functions ограничивают источники до medimind.ge и localhost
Ограничение частоты запросов Серверное ограничение на всех AI-эндпоинтах
Аутентификация Supabase anon key для edge functions; Medplum OAuth для FHIR
Передача данных Все соединения используют HTTPS/TLS
XSS в AI-ответах Markdown-рендерер санитизирует HTML перед отображением
