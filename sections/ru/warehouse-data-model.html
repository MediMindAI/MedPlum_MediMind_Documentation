9 Модель данных и архитектура

В этом разделе документируются модель данных FHIR, система разрешений и бизнес-правила, лежащие в основе складского модуля MediMind. Раздел предназначен прежде всего для разработчиков, системных администраторов и инженеров по интеграции, которым необходимо понять, как хранятся, защищаются и обрабатываются складские данные.

Все складские ресурсы используют базовый URL http://medimind.ge/fhir для пользовательских расширений, CodeSystem и систем идентификаторов. Валюта системы -- GEL (грузинский лари).

Номенклатурная иерархия (ресурсы List)

Каталог продукции организован в многоуровневую иерархию с использованием FHIR-ресурсов List. Каждый уровень использует отдельное значение code для определения своей роли:

Уровень Код List Объем Пример
1. Категории warehouse-categories ~11 Расходные материалы, Медикаменты, Реагенты
2. Группы позиций warehouse-item-groups ~310 Шприцы, Антибиотики, Бинты
3. Медицинские позиции warehouse-medical-items ~503 Амоксициллин 500 мг, Натрия хлорид 0,9%
4. Складские позиции DeviceDefinition ~35 900 Амоксициллин 500 мг производства GlaxoSmithKline, упаковка 20 шт.
Системы идентификаторов: Каждая складская позиция имеет уникальный код в системе идентификаторов http://medimind.ge/fhir/identifier/warehouse-code. Позиции, мигрированные из устаревшей PHP EMR, также сохраняют свой оригинальный ID под http://medimind.ge/fhir/identifier/php-emr-id.

  • theft-loss -- Неучтенная потеря инвентаря

  • reconciliation -- Периодическая сверка остатков

9.3 Бизнес-правила

Складской модуль применяет ряд критически важных бизнес-правил для поддержания целостности данных, безопасности и соблюдения нормативных требований. Эти правила реализованы на уровне приложения и не могут быть обойдены через пользовательский интерфейс.

FEFO (First-Expiry-First-Out -- Первый по сроку годности -- первый на выход)

При подборе позиций для трансфера или выдачи система автоматически предлагает партию с ближайшей датой истечения срока годности. Это обеспечивает использование старых запасов в первую очередь, минимизируя потери от просроченной продукции.

Мягкое удаление

Складские позиции никогда не удаляются физически из базы данных. Вместо этого они помечаются как неактивные с помощью расширения is-deleted ресурса SupplyDelivery. Это сохраняет полную историю операций для аудита и отчетности.

  • Удаленные позиции по умолчанию скрыты из результатов поиска и выпадающих списков
  • Фильтр «Показать удаленные позиции» позволяет администраторам просматривать неактивные позиции
  • Все исторические операции, ссылающиеся на удаленные позиции, остаются нетронутыми
  • Мягко удаленные позиции могут быть повторно активированы при необходимости

Автоматически генерируемые коды

Система автоматически генерирует последовательные коды позиций в формате WH-XXXXX (напр., WH-00001, WH-00002). Эти коды присваиваются при создании и являются неизменяемыми. Используемая система идентификаторов:

http://medimind.ge/fhir/identifier/warehouse-code

Повторная аутентификация

Определенные складские операции с высоким уровнем воздействия требуют от пользователя повторного ввода пароля перед выполнением. Это обеспечивает дополнительный уровень безопасности для предотвращения случайных или несанкционированных изменений. Операции, требующие повторной аутентификации:

  • Подтверждение трансфера -- утверждение или отклонение межотделенческих трансферов
  • Подтверждение списания -- утверждение утилизации складских позиций
  • Утверждение закупки -- утверждение заявок на закупку
  • Редактирование позиции -- изменение атрибутов каталога продукции в DeviceDefinition

Двойная система отделений

MediMind использует два различных типа FHIR-ресурсов для представления отделений в зависимости от контекста:

Ресурс Используется для Пример
Location Назначение пациентов (в какой палате находится пациент) Палата А, Реанимация палата 3, Приемное койка 5
Organization Учет запасов и финансовых начислений (какому отделению принадлежит инвентарь) Приемное отделение, Хирургическое отделение, Аптека

Два типа сопоставляются по совпадению наименования. Например, пациент, назначенный в Location «Приемное», сопоставляется с Organization «Приемное» для целей складского учета. Этот двойной подход разделяет управление физическим местоположением и финансовый/складской учет.

Оптимистичные обновления UI и управление параллелизмом

Складской модуль использует оптимистичные обновления UI для мгновенной отзывчивости. Когда пользователь добавляет позицию в список расходов отделения, количество на складе уменьшается в интерфейсе мгновенно. Если серверная операция завершается с ошибкой, изменение автоматически откатывается.

Для параллельного доступа к одной записи StockQuant система использует оптимистичную блокировку со следующей стратегией:

  • Блокировка на основе ETag: Каждое обновление StockQuant включает заголовок If-Match с meta.versionId ресурса
  • Автоматический повтор: При конфликте версий (HTTP 412) система повторяет попытку до 3 раз с экспоненциальной задержкой и случайным смещением
  • Кеш остатков (два уровня): Остатки StockQuant используют двухуровневый кеш: кеш в оперативной памяти с TTL 30 секунд, подкрепленный кешем в localStorage с TTL 5 минут и проверкой целостности по FNV-хешу
  • Межвкладочная инвалидация: Инвалидация кеша транслируется между вкладками браузера через BroadcastChannel API

Средневзвешенная стоимость

При поступлении нового запаса стоимость за единицу пересчитывается по формуле средневзвешенного:

Формула: newCost = (oldQty x oldCost + receivedQty x receivedCost) / (oldQty + receivedQty)
  • Безвозмездно полученные позиции (стоимость = 0) не снижают существующую стоимость -- предыдущее средневзвешенное сохраняется
  • Все стоимости хранятся в GEL (грузинский лари)
  • Стоимость отслеживается на уровне StockQuant (для каждой комбинации позиция/местоположение/партия)

Складские зоны

Позиции классифицируются по четырем складским зонам для группировки листов подбора и приоритетной обработки. Позиции холодовой цепи и контролируемые позиции всегда подбираются первыми:

Зона Код Приоритет Описание
Холодовая цепь cold-chain 1 (Наивысший) Термочувствительные позиции, требующие хранения в холодильнике
Контролируемые controlled 2 Наркотические и контролируемые вещества, требующие безопасного обращения
Опасные hazmat 3 Опасные материалы, требующие специальных процедур обращения
Общие general 4 (Наименьший) Стандартные складские позиции без особых требований к обращению
