Складские операции

Модуль склада обеспечивает сквозное управление цепочкой поставок в MediMind. Он охватывает шесть основных операций: Приёмка товаров от поставщиков, Трансферы запасов между отделениями, оформление Заказов на снабжение, мониторинг остатков Инвентаря в реальном времени, Списание повреждённых или непригодных запасов и подача запросов на Закупки новых товаров. Каждая операция доступна из раздела администрирования склада и использует FHIR-совместимое хранение данных.

ℹ️
FHIR-ресурсы: Складские операции используют три основных типа FHIR-ресурсов: SupplyDelivery (приёмки и трансферы), SupplyRequest (заказы) и Basic (остатки инвентаря StockQuant). Все операции формируют записи аудита для обеспечения прослеживаемости.

3.1 Приёмка товаров

Страница приёмки переработана с современным интерфейсом вкладок для управления входящими товарами. В заголовке страницы расположены кнопки "Импорт из РС" и "+ Создать приёмку", а ниже -- переключатель вкладок для навигации между представлениями Истории приёмок и Аналитики.

Заголовок страницы

Заголовок страницы содержит две основные кнопки действий:

  • Импорт из РС -- Импорт приёмок непосредственно из системы Службы доходов (РС) для официально задокументированных поставок
  • + Создать приёмку -- Открыть 3-шаговый мастер создания приёмки

Представления вкладок

Под заголовком переключатель вкладок организует страницу в два представления:

  • История приёмок (со значком количества) -- Сгруппированные записи накладных, показывающие все приёмки, организованные по группам приёмки
  • Аналитика (со значком количества) -- Сводная статистика и графики для операций приёмки

Группа приёмки

Подраздел группы приёмки позволяет организовывать приёмки в логические группы для пакетной обработки и совместного отслеживания связанных поставок.

Поиск и фильтры

Сворачиваемая панель поиска и фильтров предоставляет девять полей фильтрации для сужения записей приёмок:

Просмотр импортированных товаров

При просмотре приёмки (особенно импортированной из РС), модальное окно "Просмотр товаров" предоставляет детальный обзор импортированных данных с возможностями сопоставления и отслеживания.

Модальное окно просмотра товаров включает:

  • Информационные карточки документа -- Четыре карточки в верхней части, показывающие номер документа, дату, название компании и сумму
  • Предупреждение о дублировании накладной -- Уведомление, если номер накладной уже был импортирован
  • Выбор отделения -- Выбор принимающего отделения с опцией "Приёмка без контракта"
  • Таблица сопоставленных товаров -- Каждая строка показывает количество, цену, итого и кнопку отмены сопоставления для исправления автоматического сопоставления
  • Отслеживание по товарам -- Поля номера партии и срока годности для каждой позиции

Создание приёмки

Нажмите "+ Создать приёмку" для открытия 3-шагового мастера создания приёмки:

  1. Детали поставки -- Введите поставщика, отделение, номер накладной и дату доставки
  2. Обработка товаров -- Добавьте позиции с продуктом, количеством, ценой, номером партии и сроком годности
  3. Подтверждение -- Проверьте все данные и подтвердите приёмку

Аналитика

Вкладка аналитики предоставляет сводную статистику и визуальные графики для операций приёмки, помогая менеджерам отслеживать тенденции поступления товаров.

📦
Импорт из РС: Кнопка Импорт из РС позволяет импортировать приёмки непосредственно из системы Службы доходов (РС). Импортированные данные автоматически сопоставляются с каталогом склада, а несопоставленные товары отмечаются для ручной проверки.

3.2 Трансферы

Страница трансферов управляет перемещением запасов между отделениями (представьте это как внутреннюю систему доставки). Трансфер перемещает товары из отделения-источника в отделение назначения и требует подтверждения до фактического перемещения запасов. Это предотвращает несанкционированные или случайные изменения инвентаря.

Режимы просмотра

Три вкладки организуют трансферы по различным перспективам:

  • Все трансферы -- Каждая позиция трансфера в плоском списке с фильтрацией по дате, отделению и статусу
  • Группировка -- Трансферы, сгруппированные по номеру документа, показывающие полную картину многопозиционного трансфера в одной строке
  • Ожидание подтверждения -- Только трансферы, ожидающие подтверждения, с оранжевым значком количества

Жизненный цикл трансфера

Трансферы следуют контролируемому рабочему процессу для обеспечения подотчётности:

Статус Описание Кто действует
В процессе Трансфер создан, ожидает подтверждения принимающим отделением Отправитель создаёт
Завершён Трансфер подтверждён -- запасы перемещены из источника в назначение Получатель подтверждает
Отменён Трансфер отклонён или отменён Любая сторона
Усиленная аутентификация: Создание и подтверждение трансферов требует усиленной аутентификации (повторного ввода пароля). Этот дополнительный шаг безопасности предотвращает несанкционированное перемещение запасов и создаёт журнал аудита с информацией о том, кто утвердил каждый трансфер.

Создание трансфера

Нажмите Новый трансфер, чтобы открыть модальное окно книги трансферов. Двухпанельный интерфейс позволяет выбирать товары из инвентаря отделения-источника и добавлять их в трансфер:

Поле Описание FHIR-маппинг
Дата Дата трансфера (по умолчанию: сегодня) SupplyDelivery.occurrenceDateTime
Номер документа Автоматически сгенерированный идентификатор документа трансфера SupplyDelivery.identifier
Отделение-источник Исходное отделение (выбор загружает доступный инвентарь в левую панель) Extension: source-department (ссылка на Location)
Отделение назначения Целевое отделение Extension: dest-department (ссылка на Location)
Прямое списание При включении пропускает этап подтверждения и немедленно завершает трансфер SupplyDelivery.status = 'completed' (через параметр)

Левая панель показывает все товары, доступные в отделении-источнике. Нажмите на товар, чтобы переместить его в правую панель (выбранные товары). Отрегулируйте количество по необходимости. Система проверяет, что запрошенное количество не превышает доступный запас.

Подтверждение трансфера

Вкладка ожидания подтверждения показывает трансферы, требующие подтверждения от принимающего отделения. Интерфейс подтверждения позволяет просматривать детали трансфера, при необходимости редактировать количество, подтверждать или удалять трансфер.

  • Доступ по отделениям -- Пользователи видят только трансферы, связанные с назначенными им отделениями (администраторы видят все)
  • Редактирование количества -- Получатель может корректировать количество перед подтверждением (например, если прибыло меньше товаров, чем ожидалось)
  • Валидация запасов -- Система проверяет, что в отделении-источнике ещё достаточно запасов перед завершением трансфера
  • Журнал аудита -- Подтверждение создаёт запись Provenance, связывающую действие с аутентифицированным пользователем
🔄
Данные FHIR: Трансферы хранятся как ресурсы SupplyDelivery с кодом типа transfer. Каждая позиция -- отдельный ресурс, сгруппированный по номеру документа. Подтверждение перемещает запасы через сервис StockQuant -- уменьшает остаток источника и увеличивает остаток назначения.

3.3 Заказы

Страница заказов управляет запросами на снабжение между отделениями. Когда отделению нужны расходные материалы со склада, оно создаёт заказ с указанием необходимого и от какого поставщика/склада. Заказы проходят процесс подтверждения перед исполнением.

Режимы просмотра

  • Все заказы -- Полный список всех заказов со статусом, датой, данными заказчика и получателя
  • Группировка -- Заказы, сгруппированные по номеру документа для многопозиционных заказов
  • Очередь подтверждения -- Заказы в статусе draft или active, ожидающие обработки (оранжевый значок показывает количество)

Жизненный цикл заказа

Статус Описание FHIR-статус
Черновик Заказ создан, но ещё не отправлен SupplyRequest.status = draft
Активный Заказ отправлен и ожидает исполнения SupplyRequest.status = active
Подтверждён Заказ подтверждён получателем, готов к исполнению Extension: confirmed
Завершён Заказ исполнен -- запасы доставлены Extension: complete
Отменён Заказ отменён до исполнения SupplyRequest.status = cancelled

Создание заказа

Для создания заказа доступны два варианта:

  • Книга заказов -- Двухпанельный интерфейс, аналогичный книге трансферов. Выберите отделение-заказчик и отделение-поставщик/получатель, затем выберите товары из инвентаря получателя
  • Создать накладную -- Создаёт товарную накладную из существующих подтверждённых заказов, связывая заказы с фактическими отгрузками
Поле Описание FHIR-маппинг
Дата Дата заказа SupplyRequest.occurrenceDateTime
Номер документа Автоматически сгенерированный или введённый вручную номер заказа SupplyRequest.identifier
Отделение-заказчик Отделение, размещающее заказ Extension: requester-department (ссылка на Location)
Отделение-получатель Склад/поставщик, исполняющий заказ (выбор загружает доступный инвентарь) Extension: receiver-department (ссылка на Location)
📋
Позиции заказа: Каждый заказ может содержать несколько позиций. Позиции хранятся как JSON-расширение ресурса SupplyRequest, включая код товара, название, единицу измерения и количество для каждого продукта.

3.4 Инвентарь и запасы

Страница инвентаря обеспечивает просмотр уровней запасов по всем отделениям в реальном времени. Она использует систему материализованных остатков под названием StockQuant -- представьте это как живую бухгалтерскую книгу, которая мгновенно обновляется при приёмке, перемещении или потреблении товаров, вместо пересчёта из полной истории транзакций каждый раз.

Вкладка уровней запасов

Основной вид инвентаря отображает фильтруемую таблицу всех складских позиций. Каждая строка представляет уникальную комбинацию продукта, местоположения, номера партии и статуса качества.

Столбец Описание
Код Код продукта из каталога
Товар Название продукта
Тип Категория/тип товара
Количество Текущий уровень запаса; показывает разбивку доступно/всего при наличии зарезервированных товаров; значок «нет в наличии» при нулевом количестве
Цена Цена за единицу
Итого Общая стоимость (количество x цена)
Единица Единица измерения
Срок годности Дата истечения срока годности с цветными значками: красный (просрочено), оранжевый (скоро истекает), жёлтый (в зоне предупреждения)
Серия/Партия Номер партии/лота со значком статуса качества (карантин -- жёлтый, отклонено -- красный)

Фильтры

Панель фильтров предоставляет множество способов сужения инвентаря:

  • Отделение -- Выберите конкретный склад или отделение для просмотра его запасов
  • Группа товаров -- Фильтрация по категории продукта
  • Флажки количества -- Показать/скрыть нулевые остатки, ненулевые остатки или отрицательные остатки
  • Группированный вид -- Агрегация количества по партиям для одного продукта
  • Статус запасов -- Быстрый фильтр: Все, Мало на складе, Нет в наличии, Истекает, Просрочено
  • Зона -- Фильтрация по зоне склада (Холодная цепь, Контролируемые, Опасные, Общие)
  • Кросс-локационный поиск -- Поиск продукта по всем отделениям, чтобы узнать, где он есть в наличии

Таблица поддерживает встроенный поиск по коду и названию продукта, фильтрацию по ценовому диапазону и диапазону сроков годности. Результаты разбиты на страницы (50 позиций на страницу) и могут быть экспортированы в Excel.

📊
История транзакций: Нажмите на любую строку в таблице остатков, чтобы открыть модальное окно истории транзакций, которое показывает все движения запасов (приёмки, трансферы, корректировки), повлиявшие на текущий остаток для данного товара и местоположения.

Очередь комплектации (FEFO)

Вкладка очереди комплектации показывает утверждённые трансферы, требующие физического исполнения. Когда трансфер утверждён, он появляется здесь как запрос на комплектацию. Система использует логику FEFO (First Expired, First Out -- первым истекает, первым уходит) для рекомендации, из какой партии комплектовать -- товары, ближайшие к истечению срока годности, предлагаются первыми.

Процесс комплектации состоит из двух этапов:

  1. Выберите запрос на трансфер -- Выберите из списка ожидающих карточек трансфера. Каждая карточка показывает название товара, отделения-источник/назначения, требуемое количество и статус
  2. Комплектация по партиям -- Система запрашивает записи StockQuant для отделения-источника и отображает доступные партии, отсортированные по дате истечения срока годности (самые ранние первыми). Первая партия отмечена как рекомендация FEFO
Столбец списка комплектации Описание
Код / Название продукта Комплектуемый продукт
Ячейка хранения Физическое местоположение хранения на складе
Номер партии Идентификатор партии/лота для прослеживаемости
Срок годности Дата истечения срока годности партии (ключ сортировки FEFO)
Запрошенное количество Сколько единиц требуется для трансфера
Рекомендуемая комплектация Рекомендуемое FEFO количество из данной партии (ограничено доступным запасом)
Подтверждённая комплектация Фактическое количество, скомплектованное оператором склада
Переопределение FEFO: Если вам необходимо комплектовать из другой партии, отличной от рекомендации FEFO (например, если ближайшая партия имеет повреждение упаковки), вы можете переопределить предложение. Система попросит указать причину переопределения, которая фиксируется для целей аудита.
🔍
Модель данных StockQuant: Каждая запись StockQuant -- это FHIR-ресурс Basic с составным ключом itemCode | locationId | lotNumber | qualityStatus. Это обеспечивает поиск остатков за O(1) вместо пересчёта из полной истории транзакций. Статусы качества включают: принято (доступно для использования), карантин (на проверке) и отклонено (непригодно).

3.5 Списание

Страница списания управляет удалением повреждённых, просроченных или иным образом непригодных запасов из инвентаря. Когда товары невозможно продать или использовать (например, просроченные медикаменты или сломанное оборудование), документ списания официально удаляет их из системы и соответственно обновляет остатки запасов.

Режимы просмотра

Страница организует списания по трём вкладкам:

  • История -- Все документы списания в плоской таблице, отсортированной по дате, с номером документа, отделением, причиной, итоговой стоимостью и статусом
  • Аналитика -- Списания, сгруппированные по номеру документа, обеспечивающие консолидированный просмотр многопозиционных списаний
  • Ожидание подтверждения -- Списания, ожидающие утверждения перед завершением, с оранжевым значком количества

Столбцы таблицы

Столбец Описание
Номер документа Уникальный идентификатор документа списания
Дата Дата создания списания
Отделение Склад или отделение, из которого удаляются запасы
Причина Причина списания (истечение срока, повреждение, несоответствие качеству и т.д.)
Итоговая стоимость Суммарная стоимость всех списанных позиций
Статус Текущий значок статуса (в процессе, завершено или отменено)

Жизненный цикл списания

Статус Описание Кто действует
В процессе Списание создано, ожидает подтверждения авторизованным пользователем Создатель подаёт
Завершено Списание утверждено -- запасы окончательно удалены из остатков Утверждающий подтверждает
Отменено Списание отклонено или отменено до завершения Любая сторона

Создание списания

Нажмите кнопку Создать списание, чтобы открыть модальное окно создания списания. Форма использует двухпанельную компоновку: выберите товары из текущего инвентаря отделения слева, затем отрегулируйте количество и укажите причину справа.

Поле Описание FHIR-маппинг
Дата Дата списания (по умолчанию: сегодня) SupplyDelivery.occurrenceDateTime
Номер документа Автоматически сгенерированный уникальный идентификатор SupplyDelivery.identifier
Отделение Исходное отделение, из которого списываются товары Extension: source-department (ссылка на Location)
Причина Причина списания (свободный текст или предопределённая категория) Extension: writeoff-reason

Аналитический вид

Вкладка аналитики группирует списания по номеру документа, предоставляя сводный вид с общим количеством позиций и стоимостью каждого документа списания. Это полезно для аудита и отчётности по потерям запасов.

Ожидание подтверждения

Вкладка ожидания подтверждения показывает списания, требующие утверждения авторизованным пользователем до фактического удаления запасов. Этот этап утверждения гарантирует, что списания проверяются до окончательного воздействия на остатки инвентаря.

🗑
Данные FHIR: Списания хранятся как ресурсы SupplyDelivery с кодом типа write-off. Каждая позиция -- отдельный ресурс, сгруппированный по номеру документа. Подтверждение окончательно уменьшает остаток StockQuant для исходного отделения.

3.6 Закупки

Страница закупок управляет запросами на приобретение новых запасов. Когда складу необходимо закупить товары у внешних поставщиков, подаётся запрос на закупку с указанием позиций, количества и уровня приоритета. Запросы проходят многоэтапный процесс утверждения перед отправкой поставщикам.

Режимы просмотра

Страница организует запросы на закупку по трём вкладкам:

  • История запросов -- Все запросы на закупку в таблице с номером запроса, датой, заказчиком, приоритетом, статусом и итоговой стоимостью
  • Аналитика -- Запросы, сгруппированные для сводной отчётности и анализа расходов
  • Ожидание утверждения -- Запросы, ожидающие рассмотрения и авторизации, с оранжевым значком количества

Столбцы таблицы

Столбец Описание
Номер запроса Уникальный идентификатор запроса на закупку
Дата Дата подачи запроса
Заказчик Отделение или пользователь, инициировавший запрос
Приоритет Уровень срочности запроса с цветным значком (обычный, срочный, критический)
Статус Текущий статус рабочего процесса
Итоговая стоимость Ориентировочная общая стоимость запрошенных товаров

Создание запроса на закупку

Нажмите кнопку Новый запрос, чтобы открыть модальное окно создания закупки. Форма включает поля заголовка для метаданных запроса и раздел позиций для указания продуктов и количества.

Поле Описание FHIR-маппинг
Дата Дата запроса (по умолчанию: сегодня) SupplyRequest.authoredOn
Номер запроса Автоматически сгенерированный уникальный идентификатор SupplyRequest.identifier
Заказчик Отделение, подающее запрос на закупку SupplyRequest.requester (ссылка на Location)
Приоритет Уровень срочности (обычный, срочный, критический) SupplyRequest.priority
Поставщик Целевой поставщик для закупки (необязательно при создании) SupplyRequest.supplier (ссылка на Organization)

Ожидание утверждения

Вкладка ожидания утверждения показывает запросы на закупку, ожидающие авторизации. Утверждающие могут просмотреть детали запроса, при необходимости скорректировать количество, утвердить или отклонить запрос.

Детальный просмотр запроса

Нажмите на любую строку в истории запросов, чтобы открыть модальное окно детального просмотра (только для чтения). Оно показывает полную информацию о запросе, включая все позиции, историю утверждения и текущий статус.

🛒
Данные FHIR: Запросы на закупку хранятся как ресурсы SupplyRequest с расширением типа запроса purchase-request. Позиции хранятся как JSON-расширение, а процесс утверждения отслеживается через расширения статуса и записи Provenance.
