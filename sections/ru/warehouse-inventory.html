Остатки на складе

Вкладка Остатки на складе предоставляет просмотр текущих складских остатков по всем отделениям больницы в реальном времени. Представьте её как живую таблицу, которая всегда отражает актуальное состояние запасов -- каждое поступление, перемещение и списание обновляет данные автоматически.

Панель фильтров

Панель фильтров в верхней части позволяет сузить отображение остатков до нужных позиций. Фильтры расположены в два ряда:

Ряд 1 -- Основные фильтры:

  • Дата -- Просмотр остатков на определённую дату (по умолчанию -- сегодня)
  • Отделение -- Выбор конкретного отделения (выпадающий список с поиском). При пустом значении отображаются все отделения
  • Группа -- Фильтрация по типу/группе товара (например, Медикаменты, Расходные материалы)
  • Складская группа -- Фильтрация по верхнеуровневой складской категории

Ряд 2 -- Фильтры по наличию: Визуальная полоса чекбоксов для быстрой фильтрации по статусу запасов:

  • Показать нулевые -- Включить позиции с нулевым количеством (нет в наличии)
  • Показать ненулевые -- Включить позиции с положительным остатком (включено по умолчанию)
  • Показать отрицательные -- Включить позиции с отрицательным балансом (расхождения в данных)
  • Группировка -- Объединить несколько партий одного товара в сворачиваемые групповые строки
Фильтрация по зонам: Опциональный сегментированный переключатель зон позволяет фильтровать по зоне хранения: Холодовая цепь, Контролируемые, Опасные или Общие. Это удобно для складских работников, управляющих товарами с температурным режимом или ограниченным доступом.

Поиск и экспорт

Над строками таблицы расположена компактная панель фильтрации для быстрого поиска по загруженным данным:

  • Поиск по коду -- Фильтрация по коду товара
  • Поиск по названию -- Фильтрация по названию товара (частичное совпадение)
  • Диапазон цен -- Фильтрация по минимальной и максимальной цене за единицу
  • Диапазон сроков годности -- Фильтрация по окну срока годности с помощью выбора дат
  • Экспорт в Excel -- Экспорт всех видимых данных в файл электронной таблицы одним нажатием
  • Обновить -- Принудительная перезагрузка данных с сервера (обходит 30-секундный кэш)
Горячая клавиша: Нажмите Enter в любом поле поиска для немедленного применения всех фильтров.

Модель данных FHIR

Остатки на складе хранятся как ресурсы Basic с кодом stock-quant. Каждая запись StockQuant представляет уникальную комбинацию товара, местоположения, номера партии и статуса качества.

Концепция Ресурс FHIR Ключевое расширение
Остаток на складе Basic (code: stock-quant) sq-quantity, sq-unit-cost, sq-expiry-date
Местоположение Location / Organization sq-location-id, sq-location-name
Справочник товаров DeviceDefinition sq-item-code, sq-item-name
Учёт партий Basic (stock-quant) sq-lot-number, sq-quality-status
Зарезервированное кол-во Basic (stock-quant) sq-reserved-quantity
Составной ключ: Каждый StockQuant однозначно идентифицируется комбинацией itemCode | locationId | lotNumber | qualityStatus. Товары без учёта партий используют значение "NONE" в качестве номера партии.

Очередь комплектации

Очередь комплектации -- это место, где складской персонал выполняет одобренные заявки на перемещение. Когда перемещение между отделениями одобрено, оно появляется здесь в виде карточки «ожидающей заявки». Комплектовщик выбирает заявку, просматривает лист комплектации и подтверждает фактически набранное количество с полок.

Процесс комплектации

Процесс комплектации состоит из трёх этапов:

1. Выбор заявки

Выберите ожидающее перемещение из списка заявок

Отображается название товара, отделения-источник/получатель, количество и статус

2. Комплектация

Просмотр листа комплектации с рекомендованными партиями по FEFO

Ввод подтверждённых количеств и сканирование штрихкодов

3. Подтверждение

Отправка подтверждённых количеств

Запас списывается из источника и зачисляется в отделение-получатель

Карточки ожидающих заявок

Каждая одобренная заявка на перемещение отображается как кликабельная карточка, содержащая:

  • Название товара -- Запрашиваемый продукт
  • Маршрут -- Отделение-источник → отделение-получатель
  • Количество -- Запрошенное количество с единицей измерения (в синем значке)
  • Статус -- «В процессе» для активных заявок

Нажмите на карточку, чтобы загрузить лист комплектации. Выбранная карточка получает синюю левую границу и тень для обозначения активного состояния.

Таблица листа комплектации

При выборе заявки система запрашивает реальные складские данные (записи StockQuant) отделения-источника и формирует лист комплектации, отсортированный по принципу FEFO (First-Expiry-First-Out -- первым истекает, первым отгружается): партии с ближайшим сроком годности отображаются первыми.

Наименование товара Название товара. Отображает зелёный значок «Рекомендовано FEFO» на партии, которую система рекомендует комплектовать первой

FEFO -- первым истекает, первым отгружается

Система FEFO обеспечивает отгрузку товаров с ближайшим сроком годности в первую очередь, сокращая потери. Вот как это работает:

  • Система автоматически сортирует доступные партии по дате истечения срока годности (ближайшие -- первыми)
  • Первая партия в отсортированном списке получает зелёный значок «Рекомендовано FEFO»
  • Просроченные и карантинные партии исключаются из листа комплектации
  • Партии без даты истечения срока сортируются в конец списка (комплектуются последними)
Переопределение FEFO: Если комплектовщик выбирает партию, которая НЕ является рекомендованной FEFO, система открывает модальное окно с запросом причины. Частые причины: запрос клиента, состояние упаковки, неполный паллет или контроль качества. Причина переопределения и необязательные заметки фиксируются для целей аудита.

Группировка по зонам

Позиции листа комплектации группируются по зонам хранения склада, чтобы комплектовщик мог обрабатывать одну зону за раз, вместо того чтобы перемещаться между зонами. Каждая зона имеет сворачиваемый заголовок:

Зона Иконка Описание
Холодовая цепь Снежинка (синяя) Товары с температурным режимом (вакцины, биопрепараты)
Контролируемые Замок (красный) Товары с ограниченным доступом (наркотические средства, контролируемые вещества)
Опасные Биоопасность (оранжевая) Опасные материалы, требующие особого обращения
Общие Коробка (серая) Товары стандартного хранения (большинство расходных материалов и медикаментов)

Сканирование штрихкодов

Лист комплектации содержит поле ввода для сканера штрихкодов в верхней части. При сканировании штрихкода (или ручном вводе с нажатием Enter):

  • Система ищет совпадение по штрихкоду или коду товара
  • При обнаружении совпадающая строка подсвечивается визуальным пульсом, и фокус переключается на поле ввода количества
  • Звуковой сигнал подтверждает сканирование: высокий тон при успехе, низкий тон при отсутствии совпадения
  • Подсветка автоматически исчезает через 3 секунды

Отслеживание прогресса

Индикатор прогресса в заголовке показывает общий процент завершения комплектации. Полностью скомплектованные позиции считаются как 100%, частично -- как 50%. Процент обновляется в реальном времени по мере подтверждения количеств комплектовщиком.

Списания

Списания удаляют товары из учёта, когда они больше не могут быть использованы -- просроченные медикаменты, повреждённые расходные материалы, недостачи, обнаруженные при инвентаризации, или товары, отозванные производителем. Модуль списаний обеспечивает полный аудиторский след от создания до утверждения.

Фильтры

Элементы управления фильтрами над таблицей позволяют сузить отображение истории:

  • Диапазон дат -- Фильтрация по начальной и конечной дате
  • Отделение -- Фильтрация по отделению (выпадающий список с поиском)
  • Номер документа -- Поиск по конкретному номеру документа
  • Складская группа -- Фильтрация по категории товара
  • Поиск по товару -- Поиск по названию или коду товара

Итоговая строка под таблицей показывает общее количество записей и общую денежную стоимость всех видимых списаний красным цветом.

Коррекция: Завершённые списания можно скорректировать, нажав иконку корректировки в строке. Откроется модальное окно коррекции, которое создаёт обратное складское движение для отмены списания.

Вкладка «Аналитика»

Вкладка Аналитика предоставляет подробный обзор активности списаний с карточками KPI, визуальными графиками и группированной таблицей документов.

Разделы аналитики

Под карточками KPI четыре сворачиваемых раздела предоставляют углублённую аналитику:

  • Топ-5 товаров -- Рейтинг наиболее часто списываемых товаров с количеством и общей стоимостью
  • Активность отделений -- Горизонтальная столбчатая диаграмма, показывающая количество списаний по отделениям, что позволяет легко выявить отделения с аномально высокими объёмами списания
  • Распределение по причинам -- Горизонтальная столбчатая диаграмма, показывающая количество и стоимость для каждой категории причин списания
  • Сводка по периодам -- Таблица с переключением между недельным и месячным видами, показывающая количество документов и общую стоимость за период

Под аналитикой расположены панель фильтров и группированная таблица документов для просмотра отдельных документов списания с их агрегированными итогами.

Правила валидации

  • Должен быть выбран хотя бы один товар
  • Количество каждого товара должно быть больше нуля и не превышать текущий остаток
  • Поле «Причина» не должно быть пустым
  • Отделение должно быть выбрано до добавления товаров
  • Закрытие модального окна с несохранёнными товарами вызывает диалог подтверждения

Подтверждение и отклонение

  • Подтвердить -- Утверждает списание. Товар окончательно списывается со склада. Требуется повышенная аутентификация (повторный ввод пароля)
  • Отклонить -- Открывает модальное окно, где проверяющий может указать необязательную причину отклонения. Списание отменяется, запасы остаются без изменений. Также требуется повышенная аутентификация
Требуется разрешение: Кнопки «Подтвердить» и «Отклонить» активны только для пользователей с разрешением confirm-write-off или администраторов. Пользователи без этого разрешения видят неактивные кнопки.

Детальный вид при раскрытии

При раскрытии строки документа отображается подтаблица с каждой позицией, содержащая столбцы: Наименование, Единица, Количество, Цена, Итого и Причина. Это позволяет проверяющему детально изучить каждую позицию перед принятием решения об утверждении.

Модель данных FHIR

Списания хранятся как ресурсы SupplyDelivery с кодом типа write-off. Каждая позиция -- это отдельный ресурс SupplyDelivery, объединённый с другими позициями через общее расширение с номером документа.

Поле Путь FHIR Описание
Номер документа SupplyDelivery.extension (document-number) Объединяет несколько позиций в один документ
Отделение SupplyDelivery.destination Ссылка на ресурс Location
Товар SupplyDelivery.suppliedItem.itemReference Ссылка на DeviceDefinition (справочник товаров)
Количество SupplyDelivery.suppliedItem.quantity Списываемое количество
Цена SupplyDelivery.extension (unit-price) Себестоимость единицы на момент списания
Причина SupplyDelivery.extension (reason) Текстовое обоснование списания
Статус SupplyDelivery.status in-progress (ожидает), completed (утверждено), abandoned (отклонено)
Влияние на запасы: При подтверждении списания система уменьшает соответствующую запись StockQuant и инвалидирует кэш остатков. Изменение запасов немедленно отражается на вкладке «Остатки на складе» и в любом другом представлении, считывающем данные инвентаризации.
