13 Inventory Balances

13.1 Overview

The Inventory Balances dashboard provides a real-time, read-only view of current inventory levels across all hospital departments. It computes stock quantities by aggregating FHIR SupplyDelivery resources, combining receipts and inter-department transfers into a single unified balance per item per department.

Key characteristics of the Balances module:

  • Read-only dashboard -- no create, update, or delete operations are available
  • Real-time computation -- balances are calculated on-the-fly from SupplyDelivery resources
  • 12 distinct filter options across two filtering levels (top bar + in-table)
  • 9-column data table with desktop table and mobile card layouts
  • 30-second TTL cache per department for optimal performance
  • Excel/CSV export with Georgian-language headers and UTF-8 BOM encoding

13.2 Balance Calculation Formula

The core formula that drives all inventory balance calculations is as follows:

Balance Calculation Formula: 
Balance = Completed Receipts (to dept) + Completed Transfers (to dept) - Completed Transfers (from dept)
  • Only resources with status = 'completed' are included in the calculation
  • Resources with status = 'in-progress' are explicitly excluded
  • Results are cached for 30 seconds per department
  • A negative balance indicates more items transferred out than received
Component FHIR Resource Filter Criteria Effect on Balance
Receipts SupplyDelivery (type=receipt) status=completed, destination=dept + Increases
Inbound Transfers SupplyDelivery (type=transfer) status=completed, destination=dept + Increases
Outbound Transfers SupplyDelivery (type=transfer) status=completed, source=dept - Decreases

Negative Quantity Highlighting

When an item has a negative quantity or total, the values are displayed in red bold text to draw immediate attention:

Negative Balances:

A negative balance indicates that more items have been transferred out of a department than have been received. This typically signals a data entry error or a transfer that was completed before the corresponding receipt was confirmed. Investigate promptly.

13.7 Export

The Balances module provides Excel/CSV export functionality, allowing users to download the current filtered view as a spreadsheet:

Property Value
Format CSV (comma-separated values)
Encoding UTF-8 with BOM (Byte Order Mark) for Georgian character support
Headers Georgian-language column names
Filename balances_YYYYMMDD.csv (date of export)
Data Scope Current filtered and visible data only
Trigger Excel button in the in-table filter row
Export Implementation:
  • The CSV file includes a UTF-8 BOM (\uFEFF) prefix so Microsoft Excel correctly renders Georgian characters
  • The export uses the browser's built-in Blob and URL.createObjectURL APIs for client-side download
  • Only the currently filtered data is exported -- apply filters before exporting to narrow results

13.8 Caching Pattern

The Balances module employs a 30-second TTL (Time-To-Live) cache to prevent redundant API calls during rapid navigation and filter changes:

Cache Implementation:
  • TTL: 30 seconds per cached entry
  • Cache Key: departmentId or '__all__' when no department is selected
  • Storage: In-memory Map within the balance service module
  • Scope: Balance computation results only (not raw FHIR resources)

Cache Invalidation Triggers

Trigger Source Description
Manual Refresh Refresh button (in-table) User clicks the refresh icon in the filter row
Search Button Top filter bar Explicitly re-fetches when user applies new filters
Receipt Confirmation ReceptionPage Creating or confirming a receipt invalidates the affected department cache
Transfer Completion TransferConfirmationPage Completing a transfer invalidates both source and destination department caches
Important: Cache invalidation is the responsibility of the calling page/hook. FHIR services do not auto-invalidate. If a new receipt or transfer is confirmed on a different page, the Balances cache will only refresh after the 30-second TTL expires or the user manually clicks Refresh.

13.9 Quantity State Filters

The three quantity checkboxes control which items appear in the table based on their computed balance value:

Checkbox Default When Checked When Unchecked
showZeros false Items with quantity === 0 are shown Items with zero balance are hidden
showNonZeros true Items with quantity > 0 are shown Items with positive balance are hidden
showNegative false Items with quantity < 0 are shown Items with negative balance are hidden
Edge Case -- All Checkboxes Unchecked:

If all three quantity checkboxes are unchecked, the table displays no items. This is intentional behavior: since no quantity range is selected, no items match the filter criteria. The empty state with a centered red "0" will appear.

Filter Application Logic

flowchart TD A[All Balance Items] --> B{showNonZeros?} A --> C{showZeros?} A --> D{showNegative?} B -->|Yes| E["qty > 0 items included"] C -->|Yes| F["qty === 0 items included"] D -->|Yes| G["qty < 0 items included"] B -->|No| H["qty > 0 items excluded"] C -->|No| I["qty === 0 items excluded"] D -->|No| J["qty < 0 items excluded"] E --> K[Union of Included Items] F --> K G --> K K --> L[Apply Code/Name/Price/Expiration Filters] L --> M[Display Results]

13.10 Troubleshooting

Common issues encountered when using the Inventory Balances dashboard:

Issue Balance shows zero for items that were recently received
Cause: The receipt has status = 'in-progress' and has not been confirmed yet
Solution: Navigate to ReceptionPage and confirm the receipt to change its status to completed
Issue Stale data after confirming a receipt on another page
Cause: The 30-second cache has not yet expired
Solution: Click the Refresh button in the in-table filter row to force cache invalidation
Issue Table appears empty with no results
Cause: All quantity checkboxes (zeros, non-zeros, negative) may be unchecked
Solution: Ensure at least one quantity checkbox is checked. The default is showNonZeros = true
Issue Negative balances appearing unexpectedly
Cause: Outbound transfers were confirmed before corresponding receipts were completed
Solution: Review the department's transfer and receipt history. Confirm any pending receipts to correct the balance
Issue Excel export shows garbled characters for Georgian text
Cause: Spreadsheet application is not reading the UTF-8 BOM correctly
Solution: Open the CSV in Excel using "Import from CSV" and explicitly select UTF-8 encoding
Issue Department dropdown shows too many options
Cause: The system loads all ~60 departments from the FHIR server
Solution: Use the search/type-ahead feature within the department Select to quickly find the target department
