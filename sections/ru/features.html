Поиск пациента и форма регистрации

2.1 Система поиска пациентов

Единая система поиска пациентов предоставляет возможности быстрого поиска пациентов как с помощью быстрого поиска, так и с расширенными параметрами фильтрации. Поиск поддерживает запросы в реальном времени по мере ввода и интеллектуальное определение шаблонов поиска.

Быстрый поиск

Основная строка поиска принимает два типа запросов:

  • Поиск по имени: Введите любую часть имени или фамилии пациента (минимум 2 символа)
  • Поиск по личному номеру: Введите цифры для поиска по грузинскому личному идентификационному номеру
ℹ️
Комбинация клавиш: Нажмите Cmd+K (Mac) или Ctrl+K (Windows/Linux) для быстрой фокусировки на поле поиска из любого места на странице.

Расширенные фильтры

Нажмите кнопку Расширенные для доступа к дополнительным критериям поиска:

Поле фильтра Описание Путь FHIR
Личный номер Грузинский 11-значный личный идентификационный номер Patient.identifier (system: urn:oid:2.16.840.1.113883.3.3785.100.1.1)
Имя Имя (имена) пациента Patient.name[0].given
Фамилия Фамилия пациента Patient.name[0].family
Регистрационный номер Регистрационный номер визита в больницу (формат: XXXXX-YYYY) Encounter.identifier

Результаты поиска

Результаты поиска появляются в выпадающем списке под строкой поиска, показывая до 10 пациентов для быстрого поиска или 20 для расширенного поиска. Каждый результат отображает:

  • Имя пациента с личным номером и датой рождения
  • Новый визит кнопка — Открывает модальное окно создания визита
  • Заполнить форму кнопка — Заполняет регистрационную форму данными пациента для редактирования
⌨️
Навигация с клавиатуры: Используйте клавиши со стрелками ↑ и ↓ для навигации по результатам, Enter для выбора и Esc для закрытия выпадающего списка.

2.2 Разделы формы

Регистрационная форма организована в 9 сворачиваемых разделов, которые адаптируются в зависимости от того, создаете ли вы нового пациента или редактируете существующего. Форма включает интеллектуальные функции, такие как автосохранение черновиков, поиск пациентов и переключатель создания визита.

Поиск пациента

Введите 11-значный личный номер для поиска существующих пациентов перед созданием новой записи:

  • Автоматически ищет при вводе 11 цифр
  • Проверяет личный номер с использованием алгоритма контрольной суммы Луна
  • Если пациент найден, отображает карточку пациента и сворачивает демографические разделы
  • Показывает количество амбулаторных и стационарных визитов для существующих пациентов

Отображение найденного пациента

Когда существующий пациент найден, форма отображает карточку пациента и сворачивает демографические разделы для упрощения регистрации визита:

Полный вид формы

Единая регистрационная форма объединяет демографические данные пациента и информацию о визите в едином интерфейсе:

Автосохранение черновика

Форма автоматически сохраняет вашу работу в localStorage браузера по мере ввода. Индикатор черновика появляется при обнаружении несохраненных изменений:

Сохранение черновика происходит автоматически после 1 секунды бездействия. Черновик сохраняется между сеансами браузера и может быть очищен с помощью кнопки "Очистить черновик" в индикаторе прогресса.

Обзор разделов формы

Раздел Основные поля Состояние по умолчанию
1. Поиск пациента Личный номер (11 цифр) Всегда видимый
2. Личная информация Имя, Фамилия, Пол, Дата рождения, Отчество Открыт
3. Контактная информация Телефон (международный формат), Email, Адрес Свернут
4. Дополнительные детали Гражданство, Семейное положение, Образование, Место работы, Город, Район Свернут
5. Опекун/Представитель Отношение, Личный номер, Имя, Контакт (обязательно для несовершеннолетних) Свернут
6. Регистрация Дата/Время визита, Тип поступления, Статус, Отделение Открыт (если включено создание визита)
7. Страхование Компания, Тип, Номер полиса, Даты действия (до 3 страховщиков) Открыт (если включено создание визита)
8. Гарантия Виртуальный аванс, Донор, Сумма, Срок, Номер письма Свернут
9. Демография Регион, Район, Город, Адрес, Образование, Семейное положение, Занятость Открыт (если включено создание визита)
Примечание: Разделы 6-9 (Регистрация, Страхование, Гарантия, Демография) видны только при включенном переключателе Создать визит. Это позволяет зарегистрировать нового пациента без немедленного создания визита или обновить информацию о пациенте для существующих пациентов.

2.3 Дополнительные данные

Раздел дополнительных данных собирает дополнительную информацию о пациенте помимо основных персональных данных. Сюда входят семейное положение, гражданство, место работы и другие демографические сведения.

  • Семейное положение — выберите из стандартных вариантов (холост/не замужем, женат/замужем, разведён/разведена, вдовец/вдова)
  • Гражданство — укажите страну гражданства пациента
  • Место работы — запишите текущего работодателя или место работы пациента
  • Город, район — дополнительные адресные данные для точного отслеживания местоположения
📋
Сопоставление FHIR: Дополнительные данные хранятся как расширения ресурса Patient, с использованием стандартных URL-адресов расширений FHIR для семейного положения (Patient.maritalStatus) и пользовательских расширений для гражданства и места работы.

2.4 Боковая панель рабочего стола

На настольных устройствах (экраны шире 1025px) боковая панель отображает списки сегодняшних визитов и недавно зарегистрированных пациентов в реальном времени. Боковая панель обеспечивает быстрый доступ к активным пациентам без прерывания вашей текущей работы.

Раздел визитов сегодня

Отображает все встречи, созданные сегодня, показывая:

  • Значок времени указывающий, когда визит был зарегистрирован
  • Значок статуса (например, "в процессе", "прибыл", "завершен")
  • Имя пациента и регистрационный номер
  • Тип визита (например, "Амбулаторный", "Стационарный")

Нажмите на любую карточку визита, чтобы открыть модальное окно с деталями визита.

Раздел недавних пациентов

Показывает 5 самых недавно обновленных пациентов EMR (исключая пациентов портала), отображая:

  • Имя пациента
  • Личный номер и дата рождения
  • Новый визит кнопка для быстрого создания визита
  • Просмотр кнопка для открытия деталей пациента
🔄
Автообновление: Оба раздела автоматически обновляются при создании новых пациентов или визитов. Список недавних пациентов получает 30 самых недавно обновленных пациентов и фильтрует пациентов портала, отображая топ 10 пациентов EMR.

2.5 Мобильный мастер

На мобильных устройствах (экраны уже 768px) регистрационная форма преобразуется в пошаговый мастер с фиксированной навигацией внизу. Этот оптимизированный для мобильных устройств интерфейс обеспечивает доступность всех полей формы на маленьких экранах.

Шаги мастера

Шаг Включенные разделы
1. Пациент Поиск пациента, Личная информация
2. Личная инфо Личная информация (продолжение)
3. Контактная инфо Контактная информация, Дополнительные детали, Опекун
4. Регистрация Регистрация визита, Страхование (если включено создание визита)
5. Страхование Детали страхования, Гарантия, Демография (если включено создание визита)
  • Индикатор прогресса показывает текущий шаг и статус завершения
  • Фиксированные кнопки действий остаются доступными при прокрутке
  • Кнопки Назад/Далее для навигации по шагам
  • Кнопка Отправить появляется на последнем шаге

2.6 Раздел регистрации

Раздел регистрации настраивает основные параметры визита при включенном переключателе Создать визит. Этот раздел создает ресурс Encounter, связанный с пациентом.

Параметры визита

Поле Описание Путь FHIR
Дата визита Дата и время регистрации визита (обязательно) Encounter.period.start
Тип поступления Амбулаторный или Стационарный (обязательно) Encounter.class
Тип стационарного Тип поступления для стационарных визитов (например, Экстренный, Плановый) Encounter.type
Статус Статус визита (например, Запланирован, Прибыл, В процессе) Encounter.status
Отделение Отделение больницы, обрабатывающее визит (обязательно, фильтруется по типу поступления) Encounter.serviceProvider (ссылка на Organization)
🏥
Фильтрация отделений: Выпадающий список отделений динамически фильтруется в зависимости от выбранного типа поступления. Амбулаторные отделения появляются для амбулаторных визитов, а стационарные отделения для стационарных визитов.

Создание встречи

Когда вы отправляете форму с включенным Создать визит, система создает ресурс Encounter:

Встреча включает:

  • Регистрационный номер — Автоматически генерируемый идентификатор (формат: XXXXX-YYYY)
  • Ссылка на пациента — Связывается с ресурсом Patient
  • Поставщик услуг — Связывается с выбранной Organization (отделение)
  • Страховое покрытие — Связывается с ресурсами Coverage, если страхование настроено

2.7 Управление страхованием

Раздел страхования позволяет настроить до 3 страховых компаний для визита пациента. Каждый страховщик хранится как ресурс FHIR Coverage.

Переключатель страхования

Раздел включает флажок для включения/отключения страхования. При отключении форма сворачивается и ресурсы Coverage не создаются. При включении появляется карточка основного страховщика.

Несколько страховщиков

Вы можете добавить до 3 страховщиков для одного визита:

  • Основной страховщик (#1) — Всегда видим при включенном страховании, не может быть удален
  • Вторичный страховщик (#2) — Нажмите "Добавить еще" для включения второго страховщика
  • Третичный страховщик (#3) — Добавьте третьего страховщика при необходимости

Поля страховщика

Поле Описание Путь FHIR
Страховая компания Название страхового провайдера (выпадающий список с поиском) Coverage.payor (ссылка на Organization)
Тип страхования Тип страхового полиса (например, Государственный, Частный) Coverage.type
Номер полиса Идентификационный номер страхового полиса Coverage.identifier
Номер направления Номер авторизации или направления от страховщика Coverage.extension (направление)
Процент доплаты Процент доплаты пациента (0-100) Coverage.costToBeneficiary
Дата выдачи Дата выдачи страхового полиса Coverage.period.start
Действителен до Дата истечения срока действия страхового полиса Coverage.period.end
🛡️
Приоритет покрытия: Каждому страховщику присваивается значение приоритета (порядка) в ресурсе Coverage. Основной = 1, Вторичный = 2, Третичный = 3. Это определяет порядок обработки претензий.

2.8 Предупреждение об активном визите

При создании нового визита для пациента, у которого уже есть активный (в процессе) визит, система отображает модальное предупреждение для предотвращения дублирующих регистраций.

Триггер предупреждения

Модальное окно появляется при выполнении всех этих условий:

  • Вы отправляете форму с включенным Создать визит
  • У пациента уже есть Encounter со status="in-progress"
  • Активная встреча была создана в течение последних 24 часов

Содержимое модального окна

Предупреждение отображает:

  • Имя пациента и личный номер
  • Список активных визитов с регистрационными номерами, типами визитов и временными метками
  • Кнопки действий: Отмена (вернуться назад) или Все равно продолжить (создать дублирующий визит)
Лучшая практика: Внимательно просмотрите детали активного визита перед продолжением. Создание дублирующих активных визитов может вызвать путаницу в истории пациента и выставлении счетов. Если визит является подлинным новым поступлением (например, экстренная повторная госпитализация), нажмите "Все равно продолжить".

2.9 Раздел демографии

Раздел демографии собирает адресную и социальную информацию для статистических и административных целей. Этот раздел виден при включенном Создать визит.

Адресная информация

Поле Описание Путь FHIR
Регион Грузинский административный регион (например, Тбилиси, Аджария) Patient.address[0].state
Район Район в выбранном регионе (фильтруется по регионам) Patient.address[0].district
Город Название города или населенного пункта Patient.address[0].city
Фактический адрес Адрес улицы и номер квартиры Patient.address[0].line

Социальная информация

Поле Описание Расширение FHIR
Образование Высший уровень завершенного образования (например, Высшее, Среднее) Patient.extension (образование)
Семейное положение Семейное положение (например, Женат/Замужем, Холост/Не замужем, Разведен(а)) Patient.maritalStatus
Занятость Статус занятости (например, Работает, Безработный, На пенсии) Patient.extension (занятость)
🗺️
Копировать от пациента: Кнопка "Копировать из контактной информации" (вверху справа раздела) автоматически заполняет поля адреса из раздела контактной информации пациента, экономя время при регистрации.
🔗
Каскадные выпадающие списки: Поле Район динамически фильтруется в зависимости от выбранного Региона. Сначала выберите регион, прежде чем выбирать район.
