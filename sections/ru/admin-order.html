12 Order System

12.1 Overview

The Order System manages inter-departmental supply orders within the MediMind EMR Administration module. Unlike the Transfer System which handles actual inventory movement, the Order System handles requests for supplies between departments.

Key Distinction - Orders vs. Transfers:
  • Orders = Requests for supplies. Quantity-only (no price or total). Uses FHIR SupplyRequest.
  • Transfers = Actual movement of inventory. Includes price and totals. Uses FHIR SupplyDelivery.
  • Orders do not store prices; prices are looked up from inventory balances at display time
  • An order may lead to one or more transfers when it is dispatched and delivered

12.2 Status Lifecycle

Orders follow a multi-step status lifecycle from creation through delivery. The system maps application statuses to FHIR SupplyRequest statuses.

stateDiagram-v2 [*] --> draft : Create Order draft --> active : Submit active --> confirmed : Confirm confirmed --> dispatched : Dispatch dispatched --> delivered : Deliver delivered --> complete : Finalize confirmed --> cancelled : Cancel complete --> [*] cancelled --> [*]
Custom FHIR Mapping:

The application status confirmed maps to the FHIR status suspended. This is because FHIR R4 SupplyRequest does not have a native "confirmed" status. The suspended status was chosen as the closest semantic match to indicate an order that has been verified but not yet dispatched.

Status Mapping

App Status FHIR Status Meaning
draft draft Order created but not yet submitted
active active Order submitted and awaiting review
confirmed suspended Order reviewed and approved; awaiting dispatch
dispatched active + extension Items have been sent from the supplying department
delivered active + extension Items received by the requesting department
complete completed Order finalized and closed
cancelled cancelled Order cancelled before dispatch

12.3 OrderPage

The OrderPage is the entry point for creating new supply orders. It provides two creation modals and a filterable table of existing orders.

OrderBookModal
Dual-panel book-style interface for quick item selection from department inventory. Best for visual selection.
WaybillCreationModal
Standard waybill form with item search, optional order linking, and supplier selection. Best for structured entry.

Below the creation buttons, a filterable OrderTable displays existing orders with status badges, department information, and action buttons.

12.4 OrderBookModal

The OrderBookModal provides a dual-panel interface for creating supply orders, allowing users to visually browse and select items from the receiver department's inventory.

Header Fields

Field Component Description
Date DatePicker Order date, defaults to current date
Document Number Auto-generated Format: ORD-YYYY-NNN (e.g., ORD-2026-001)
Requester Department Select Department requesting the supplies (requesterDeptId)
Receiver Department Select Department supplying the items (receiverDeptId). Inventory is loaded from this department.

Dual-Panel Layout

Left Panel: Available Items
Displays items from the receiver department's inventory via the useDepartmentInventory hook. Includes text filter for narrowing results.
Right Panel: Selected Items
Shows items selected for the order with quantity input fields (yellow background #FAFAAC). Maximum quantity equals current stock.
Form Validation:
  • Requester and receiver departments must be different
  • At least one item must be selected to submit the order
  • Quantity for each item must be between 1 and the available stock

12.6 OrderConfirmationPage

The OrderConfirmationPage uses a unique 3-section layout to manage order review and confirmation in a single view.

Section 1: Item Entry Form (OrderConfirmationItemForm)

This section is only visible for orders with status active. It allows adding additional items to an order before confirmation.

Section 2: Main Orders Table

Displays all orders with an inline filter row for quick searching. Each row shows the order document number, departments, date, status, and item count.

Section 3: Order Details (Inline)

When an order is selected in the table, its details expand inline below the selected row, showing all line items.

  • Line Items Display - Shows item name, code, unit, and quantity for each line item
  • Inline Editing - Click on a quantity value to transform it into a NumberInput field
  • Keyboard Support - Press Enter to save the edited value, Escape to cancel
  • Confirm Button - Changes order status to confirmed (FHIR: suspended)
Confirmation Behavior:
  • Only orders with status active can be confirmed
  • Confirming an order changes its status to confirmed, which maps to FHIR suspended
  • After confirmation, the Item Entry Form (Section 1) becomes hidden for that order
  • Confirmed orders proceed to the dispatch and delivery workflow

12.7 OrdersPage

The OrdersPage provides a flat line item view of all orders, displaying each item as a separate row rather than grouping by order. This makes it easy to search for specific items across all orders.

Feature Description
OrderLineItemRow Each row represents a single line item with a compound ID: orderId-itemId
Price Lookup (priceMap) Prices are not stored on orders; they are looked up from warehouse inventory balances at display time
Delivered Quantity (deliveredMap) Tracks quantities already delivered via completed transfers, calculated from associated transfer records
Remaining Quantity Calculated as: ordered quantity minus delivered quantity
Price Lookup Note: Orders do not store prices. Instead, prices are looked up from inventory balances at display time using the priceMap. This means the displayed price always reflects the current inventory valuation, not the price at the time the order was placed.

12.8 OrderGroupPage

The OrderGroupPage provides an aggregated view of orders, grouping all line items by document number for summary reporting.

Feature Description
Grouping Key Groups by documentNumber
Summary View Each group row shows document number, date, departments, and aggregate counts
Details Modal Clicking a group row opens a modal showing all individual line items within that order group

The details modal displays the complete list of line items across all orders sharing the same document number, including item name, code, unit, quantity, and status.

12.9 Line Items Storage

JSON Extension Storage Pattern:
  • Order line items are stored as a JSON string in the ORDER_LINE_ITEMS extension on the SupplyRequest resource
  • The JSON string is parsed on read and serialized on write
  • Each order is a single SupplyRequest resource containing all its line items in the extension (unlike receipts and transfers, where each line item is a separate FHIR resource)
  • This design reduces the number of FHIR resources but requires careful JSON serialization handling
SupplyRequest (Order)
├── status: draft | active | suspended | completed | cancelled
├── occurrenceDateTime: order date
├── identifier: ORD-YYYY-NNN document number
├── requester: requesting department reference
├── supplier: supplying department reference
└── extension[]
    ├── ORDER_LINE_ITEMS: "[{\"itemId\":\"...\",\"itemName\":\"...\",\"itemCode\":\"...\",\"unit\":\"...\",\"quantity\":5}, ...]"
    ├── REQUESTER_DEPT_NAME: department display name
    └── RECEIVER_DEPT_NAME: department display name

This differs from the Transfer System where each line item creates a separate SupplyDelivery resource. The single-resource approach for orders simplifies order-level operations (status changes, confirmation) but means line item updates require reading and rewriting the entire JSON array.

12.10 Troubleshooting

Issue Cause Solution
Same department selected for requester and receiver Validation rule requires departments to be different Select a different department for either the requester or receiver field
No items in left panel Receiver department has no inventory or useDepartmentInventory hook returned empty Verify the receiver department has inventory; check network connection and try again
Order cannot be confirmed Order status is not active; only active orders can be confirmed Check the order status; it may already be confirmed, completed, or cancelled
Prices showing as zero or empty Price lookup from warehouse balances returned no match Verify that the item exists in the warehouse inventory with a valid price
Delivered quantity not updating Associated transfers are still in in-progress status Confirm pending transfers; only completed transfers contribute to the delivered quantity
Item search returns no results searchCatalogItems found no matching catalog entries Verify search terms; try a broader query or check that the catalog is populated
Confirmed status shows as "suspended" in FHIR Expected behavior: app confirmed maps to FHIR suspended This is by design; FHIR R4 SupplyRequest lacks a native "confirmed" status
Line items lost after edit JSON serialization error in ORDER_LINE_ITEMS extension Check for special characters in item names; ensure valid JSON structure on save
Group details modal is empty No line items found for the selected document number group The orders in this group may have been deleted; check the OrdersPage for individual records
Cannot submit order - no items selected Validation requires at least one item in the order Add at least one item from the available panel before submitting
