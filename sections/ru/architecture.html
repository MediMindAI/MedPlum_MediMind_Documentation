3 Архитектура

Модуль регистрации пациентов MediMind построен на основе компонентной архитектуры с использованием React, TypeScript и платформы Medplum FHIR. Этот раздел предоставляет технический обзор структуры системы, потока данных и интеграции с ресурсами FHIR.

Обзор архитектуры

Модуль регистрации следует трехуровневой адаптивной компоновке, которая адаптируется к различным размерам экранов, сохраняя единую иерархию компонентов.

Рабочий процесс FHIR

Процесс регистрации пациентов следует многоэтапному рабочему процессу создания ресурсов FHIR, который интегрирует поиск, отправку формы и создание визита.

sequenceDiagram participant User as Пользователь participant SearchHero as Панель поиска participant Form as Форма participant Hook as useRegistrationForm participant Service as patientDataBindingService participant API as Medplum FHIR API participant Storage as localStorage User->>SearchHero: Ввести личный номер или имя SearchHero->>API: GET /Patient?identifier=01011055555 API-->>SearchHero: Patient[] (существующие пациенты) alt Пациент найден SearchHero->>Form: Автозаполнение данных пациента Form->>User: "Предупреждение об активном визите" если Encounter.status=in-progress else Пациент не найден SearchHero->>Form: Развернуть все секции (Новая регистрация) end User->>Form: Заполнить поля регистрации Form->>Storage: Автосохранение черновика (с задержкой 1 сек) User->>Form: Нажать отправить Form->>Hook: Проверка и обработка данных формы Hook->>Service: Привязка 101+ кодов GoodKey Service->>API: POST /Patient (создать/обновить) API-->>Service: Ресурс Patient opt Создать визит = true Service->>API: POST /Encounter API-->>Service: Ресурс Encounter opt Есть страховка Service->>API: POST /Coverage (для каждого страховщика) API-->>Service: Coverage[] end opt Есть опекун Service->>API: POST /RelatedPerson API-->>Service: Ресурс RelatedPerson end end Service->>Storage: Очистка черновика Service-->>User: Сообщение об успехе + Переход к истории пациента

Этапы рабочего процесса

  1. Фаза поиска: Пользователь вводит личный номер или имя → Система запрашивает существующих пациентов на сервере FHIR
  2. Поиск пациента: Если найден, автозаполняет данные пациента и проверяет активные визиты; если не найден, разворачивает все секции формы для новой регистрации
  3. Заполнение формы: Пользователь заполняет 9 секций-аккордеонов с автосохранением в localStorage (задержка 1 секунда)
  4. Проверка: Система проверяет личный номер (11-значная контрольная сумма Луна), обязательные поля и бизнес-правила
  5. Создание ресурса FHIR: При отправке создает ресурс Patient с 101+ кодами привязки данных GoodKey
  6. Создание визита (опционально): Если переключатель "Создать визит" включен, создает Encounter, Coverage (если застрахован) и RelatedPerson (если присутствует опекун)
  7. Очистка черновика: Очищает черновик localStorage и переходит к представлению истории пациента
Предупреждение об активном визите: Если у пациента уже есть Encounter.status='in-progress', система отображает модальное окно предупреждения для предотвращения дублирования активных визитов.

Ресурсы FHIR

Модуль регистрации создает и управляет следующими ресурсами FHIR R4 с грузинскими расширениями.

Ресурс Назначение Ключевые поля
Patient Основные демографические данные пациента identifier (Личный номер), name (Имя с отчеством), gender (Пол), birthDate (Дата рождения), telecom (Телефон, email), address (Адрес), extension:citizenship (Гражданство), extension:unknown-patient (Неизвестный пациент)
Encounter Запись визита/встречи пациента status (Запланирован, в процессе, завершен), class (Амбулаторный, стационарный, неотложный), type (Тип визита), subject (Ссылка на Patient), participant (Практикующие врачи), period (Дата/время визита)
Coverage Информация о страховом полисе payor (Ссылка на страховую компанию), beneficiary (Ссылка на Patient), relationship (Сам, семья), period (Действительность полиса), identifier (Номер полиса)
RelatedPerson Опекун/представитель для несовершеннолетних или недееспособных пациентов patient (Ссылка на Patient), relationship (Родитель, опекун, супруг), name (Имя), telecom (Контактная информация), address (Адрес)
Organization Отделения больницы, страховые компании identifier (Идентификатор), name (Название), type (dept, prov, ins), telecom (Телефон), address (Адрес)

Грузинские расширения FHIR

MediMind расширяет FHIR R4 для поддержки требований грузинского здравоохранения:

URL расширения Применяется к Назначение Пример значения
medimind:patronymic Patient.name Имя отца (среднее имя в грузинском именовании) "გიორგის" (сын Гиорги)
medimind:citizenship Patient Статус гражданства (гражданин, иностранец, лицо без гражданства) "citizen", "foreigner"
medimind:unknown-patient Patient Неотложный пациент без идентификации (присвоен временный ID) true / false
medimind:data-binding Patient, Encounter 101+ кодов GoodKey для стандартизации данных электронных медицинских карт Код "010101" = Имя
Расширение отчества: Грузинская конвенция именования включает имя отца в родительном падеже (например, "ნინო გიორგის ასათიანი" = Нино, дочь Гиорги, Асатиани). Это сохраняется как расширение в Patient.name.given.

Привязка данных с кодами GoodKey

MediMind использует 101+ кодов привязки данных GoodKey для стандартизации данных пациентов во всей системе электронных медицинских карт. Каждое поле формы сопоставляется с конкретным кодом:

Поле формы Код GoodKey Путь FHIR Тип данных
Личный номер 010100 Patient.identifier[0].value string (11 цифр)
Имя 010101 Patient.name[0].given[0] string
Фамилия 010102 Patient.name[0].family string
Отчество (Среднее имя) 010103 Patient.name[0].extension:patronymic string
Дата рождения 010104 Patient.birthDate date (YYYY-MM-DD)
Пол 010105 Patient.gender code (male, female, other, unknown)
Номер телефона 010201 Patient.telecom[0].value string
Email 010202 Patient.telecom[1].value string
Адрес 010301 Patient.address[0].text string
Гражданство 010401 Patient.extension:citizenship code (citizen, foreigner, stateless)
Профессия 010402 Patient.extension:occupation string
Тип визита 020101 Encounter.type[0].coding[0].code code (outpatient, inpatient, emergency)
Отделение 020102 Encounter.serviceProvider reference (Organization)
Страховая компания 030101 Coverage.payor[0] reference (Organization)
Номер полиса 030102 Coverage.identifier[0].value string

Автосохранение и восстановление черновиков

Форма регистрации включает интеллектуальное автосохранение для предотвращения потери данных:

  • Триггер: Автосохранение активируется через 1 секунду после того, как пользователь прекращает набор (с задержкой)
  • Хранение: Данные черновика сохраняются в localStorage с ключом по личному номеру пациента
  • Значок черновика: Визуальный индикатор появляется в трекере прогресса при сохранении черновика
  • Восстановление: При перезагрузке страницы система обнаруживает черновики и предлагает пользователю восстановить или удалить
  • Очистка: Черновики автоматически удаляются после успешной отправки формы
Бизнес-правило: Несовершеннолетние пациенты (<18 лет) автоматически активируют секцию опекуна, которая становится обязательной. Система определяет возраст на основе введенной даты рождения.

Правила проверки

Поле Правило проверки Сообщение об ошибке
Личный номер 11 цифр + алгоритм контрольной суммы Луна "Неверный формат или контрольная сумма личного номера"
Имя, Фамилия Обязательно (кроме режима неизвестного пациента) "Это поле обязательно"
Дата рождения Дата в прошлом, не в будущем "Дата рождения не может быть в будущем"
Номер телефона Грузинский формат: +995XXXXXXXXX или 5XXXXXXXX "Неверный формат номера телефона"
Email Формат email RFC 5322 "Неверный адрес электронной почты"
Опекун (если <18 лет) Требуется хотя бы один контакт опекуна "Информация об опекуне обязательна для несовершеннолетних"
